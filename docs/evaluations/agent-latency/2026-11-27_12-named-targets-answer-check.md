# 이름 선택지 빠른 길: 답과 서버 데이터 대조 (2026-11-27)

실제 Gemini 라우터(gemini-3.5-flash-lite, minimal)로 데모 계정에 물은 답을 같은 시각의 REST 응답과 비교했다. 평가 세트는 담당만 채점해서 답 내용은 따로 확인했다.

## 서버 데이터 (REST)

| 대상 | 값 |
|---|---|
| 카드 •••• 0017 | 분실 신고, 하루 한도 1,000,000원, 오늘 쓴 금액 0원, 사용내역 0건 |
| 카드 •••• 0033 | 사용 중, 하루 한도 1,000,000원, 오늘 쓴 금액 0원 |
| 생활비 110-101-000001 | 잔액 2,331,000원 |
| 비상금 110-101-000002 | 잔액 169,000원 |

## 질문과 답

| 질문 | 라우터가 고른 대상 | 답 | 맞음 |
|---|---|---|---|
| 체크카드 한도 얼마 남았어? | •••• 0033 (체크카드 두 장 중 사용 중인 하나) | 하루 한도 1,000,000원 중 오늘 0원을 써서 1,000,000원 남았어요 | 예 |
| 0017 카드 한도는? | •••• 0017 | 하루 한도 1,000,000원 중 오늘 0원 … 지금 분실 신고 상태라 결제할 수 없어요 | 예 |
| 생활비 통장 상세 보여줘 | 생활비 110-101-000001 | 잔액 2,331,000원, 이체 한도 1회 1,000,000원·하루 5,000,000원 | 예 |
| 비상금 통장 이체 한도 알려줘 | 비상금 110-101-000002 | 잔액 169,000원, 이체 한도 1회 1,000,000원·하루 5,000,000원 | 예 |
| 카드 한도랑 내 잔액 알려줘 | (카드 안 고름 → 사용 중인 카드 전부) | 0033 한도 + 총자산 8,100,000원과 계좌별 잔액 | 예 |

## 고친 판단 하나

- 처음 규칙에서는 그냥 "카드 사용내역 보여줘"에도 라우터가 사용 중인 카드 하나(0033)를 골랐다. 그러면 분실 카드의 지난 사용내역이 빠질 수 있다.
- 규칙을 "카드 이름·종류·끝자리를 콕 집어 말했을 때만 고르고 그냥 '카드'면 비운다"로 좁혔다.
- 고친 뒤: "카드 사용내역 보여줘" → 모든 카드("카드 최근 사용내역이 없어요."), "체크카드 0033 최근 결제 보여줘" → 0033 하나. 둘 다 약 1초.
- 그래서 10번 측정 뒤에 규칙이 바뀌었고 최종판은 11번 측정이다.
