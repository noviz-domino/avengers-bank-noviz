# 2단계 상품 화면 디자인 점검

2026-11-09 · 기준: [15 상품](15-products-option-1-selected.png), 공통 `ui.mjs` / `ui.css`.

## 반영

- 공통 머리글·목록 제목·로딩/빈 상태/오류 안내와 SVG 아이콘을 재사용했다. 기존 API, 금리 계산, 분류 유지, 가입/PIN 승인 흐름은 유지했다.
- 제목 26px, 본문 15px, 보조 글자 13px과 크림/블루/세이지 토큰을 적용하고 필터·가입·취소·목록 복귀의 터치 높이를 44px 이상으로 맞췄다.
- 긴 상품 이름과 조건은 줄바꿈하고 320px 목록은 금리를 다음 줄 오른쪽에 배치한다.
- 예금 출금 계좌를 네이티브 라디오 목록으로 바꿔 긴 별칭·마스킹 계좌번호·잔액을 각각 읽을 수 있게 했다. 첫 활성 입출금 계좌가 기본 선택되며 기존 `from_account_id` 제출값을 그대로 쓴다. 해당 계좌가 없으면 안내하고 가입 버튼을 비활성화한다.

## 실제 화면 확인

Chrome headless CDP에서 현재 로컬 API에 데모 로그인하여 390px/320px 상품 목록과 예금 가입 입력을 캡처했다. 기준 PNG와 직접 비교해 크림 대표 상품, 금리 위계, 하단 상품 목록과 색상을 확인했다. 대표 상품의 돼지 그림은 기존 SVG를 유지했으므로 기준의 입체 그림과 다르다. 서버의 실제 금리·조건·상품 개수를 표시하며 기준의 예시 문구를 복사하지 않았다.

모든 기본 캡처에서 문서 너비가 뷰포트와 같았고 보이는 버튼·링크·숫자 입력에 44px 미만 높이는 없었다. 320px에서 계좌 별칭을 DOM에만 길게 넣어 줄바꿈과 가로 넘침 없음도 확인했다. 빈 예금 분류는 순수 렌더러에 빈 배열을 전달해 안내와 `role="status"`를 확인했다. 이 두 추가 시나리오는 서버 데이터를 수정하지 않았다.

로컬 캡처: `%TEMP%/capbank-phase2/products-390.png`, `products-320.png`, `deposit-390.png`, `deposit-320.png`, `deposit-long-320.png`, `products-empty-320.png`. 임시 QA 자료로 저장했으며 저장소에는 추가하지 않았다.

## 검사와 제한

`node --test frontend/cards.test.mjs frontend/products.test.mjs`: 7개 통과. 신규 검사는 활성 입출금 계좌만 선택 가능한지, 기본 선택·마스킹·이스케이프·계좌 없음 시 비활성화와 빈 상품 분류 안내를 확인한다. `git diff --check` 통과.

가입 제출·자금 이동·PIN 승인 및 실제 네트워크 장애는 이번 디자인 점검에서 실행하지 않았다. 휴대폰 실기기 검증은 남아 있다.

## 전체 이미지 배너 후속 반영

1번 시안의 대표 상품 영역을 3:2 전체 이미지 두 장으로 교체했다. ImageGen에 크림 배경과 네이비 문구, 적금은 입체 세이지색 저금통·금화, 예금은 입체 네이비 금고·금화를 요청했다. 각 이미지에 상품명과 상세 보기 문구를 넣었고, 금리와 가입 조건은 화면에서 서버 응답을 표시한다.

예시 상품 응답으로 Chrome의 320px·390px 화면에서 이미지 비율, 가로 넘침, 앞뒤 버튼, 터치 스와이프, 분류별 배너 표시와 상품 상세 이동을 확인했다. 프론트 단위 테스트 22개가 통과했다. 실기기와 실제 백엔드 연결은 확인하지 않았다.
