# 2단계 계좌·이체 UI 확인

2026-11-09, 기준 시안 29·39~43과 HANDOFF.md를 확인했다.

## 반영

- 공통 머리글·버튼과 UI 토큰을 사용한다. 긴 별칭은 줄바꿈하고 잔액·이체 버튼의 공간을 유지한다.
- 계좌 상세는 잔액·거래내역·하단 이체에 집중한다. 상품·개설일·이체 한도·예적금 조건은 상단 관리에 모았다.
- 내 계좌 빠른 선택에 입출금 / 적금 납입을 표시한다. 예금은 수신 후보에서 제외한다.
- 금액 다음 단계에서 서버에 승인 요청을 만들고, 확인 화면에는 응답의 `summary`를 그대로 표시한다. PIN 단계는 같은 요청을 사용한다.
- 완료는 서버 실행 성공 뒤에만 표시한다. 완료 내용은 승인 응답의 `summary`, 잔액은 성공 후 계좌 상세 응답을 사용한다. 잔액 조회 실패 때는 추정값을 만들지 않는다.
- 확인 화면에서 수정·뒤로·닫기를 누르면 해당 승인 요청을 취소한다. 늦게 도착한 요청도 화면을 떠났다면 취소한다.
- 홈의 예산 가드 요약은 GET `/budget`을 사용하고 `#budget` 화면으로 이동한다.

## 검증 및 스크린샷

실제 로컬 API(8000)와 정적 프런트(8011)를 사용한 Chrome CDP 점검을 수행했다. 390×844 / 320×844에서 문서 가로 넘침이 없었고, 표시된 버튼·입력·선택 컨트롤은 높이 44px 이상이었다.

이미지를 실제로 캡처하고 열어 확인했다. 로컬 결과 폴더는 `C:/Users/USER/AppData/Local/Temp/capbank-phase2/`이며 저장소에는 이미지 사본을 추가하지 않았다.

| 캡처 | 상태 |
|---|---|
| `account-390.png` | 계좌 상세·잔액·거래내역 |
| `account-long-320.png` | 긴 별칭 줄바꿈; DOM에서만 이름 변경, DB 미수정 |
| `manage-320.png` | 계좌 정보·한도·별칭·해지 |
| `recipient-320.png` | 출금 계좌·수신 번호·계좌 종류 |
| `amount-320.png` | 금액 입력·출금 계좌 요약 |
| `review-320.png` | 서버가 생성한 출금·수신·1,000원 요약 |

QA에서 만든 1,000원 승인 요청은 닫기로 취소했고 송금은 실행하지 않았다. `node --test frontend/*.test.mjs` 21개가 통과했다. 실제 승인·완료 흐름은 공용 브라우저 통합 점검에서 별도로 확인한다.

## 차이 및 미검증

현재 승인 API는 구조화된 수신인·출금계좌 필드를 공개하지 않으므로 시안의 표 대신 서버 `summary` 문장을 사용한다. 문자열을 파싱하거나 수신인을 추측하지 않는다. PIN은 공통 승인 창을 유지하며 이미지의 전용 숫자 키패드는 추가하지 않았다.

이 보고서의 개별 QA에서는 실제 송금 완료·연결 끊김·네이티브 모바일 키보드·기기 스크린리더를 확인하지 않았다. 전체 길이 캡처에서 고정 하단 컨트롤은 캡처 시점의 뷰포트 위치에 보인다.
