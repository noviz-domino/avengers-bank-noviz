# 다음 작업 — 은행 앱과 에이전트 MVP

작성일: 2026-11-08 (Asia/Seoul)
마지막 업데이트: 2026-11-09 오후 (Asia/Seoul)

## 현재 우선순위

사용자의 최신 지시: **연동은 우선 신경 쓰지 않고 은행 앱과 에이전트 구성을 최우선으로 완성한다.**

기존 백엔드와 라우터 + 계좌·카드·상품 Agent, RAG·MCP 구조를 활용합니다. 시연 화면은 [모바일 데모 실행 방법](../../README.md#모바일-데모)에서 실행할 수 있습니다.

- 먼저: 선택한 디자인 정리 → 은행 앱 화면·화면 이동 구현 → 에이전트 역할·대화 흐름 구성 → 데모 데이터로 전체 사용 흐름 확인.
- 이후: 프론트엔드와 실제 API 연결, 실모델 통합 점검, 타행·팀원 은행 연동, 배포.
- 앞서 제안한 “API 연동과 배포부터 진행하는 MVP 계획”보다 이 문서의 최신 우선순위를 적용합니다.
- 데모 데이터로 동작하는 화면과 실제 서버에서 처리된 거래를 구분합니다. 이번 구성 단계 완료를 실제 송금·API 연결 완료로 표현하지 않습니다.

## 1차 MVP — 은행 앱 핵심 흐름과 에이전트 구성

| 순서 | 작업 | 구현·정리할 내용 | 완료 기준 |
|---|---|---|---|
| 1 | 공통 UI·화면 구조 | 모바일 레이아웃, 하단 메뉴, 상단 뒤로 가기, 버튼·입력·모달·로딩·빈 상태 | 홈·계좌·이체·AI 상담 사이를 이동할 수 있음 |
| 2 | 로그인·홈·계좌 | 데모 로그인, 총자산 숨김, 계좌 접기·펼치기, 잔액·거래내역, 계좌 관리 진입 | 일관된 데모 데이터로 로그인 → 홈 → 계좌 상세를 확인 |
| 3 | 이체·PIN 흐름 | 받는 계좌 → 금액 → 확인 → 6자리 PIN → 결과, PIN 미등록 시 등록 진입, 취소·뒤로 가기 | 데모에서 정상·취소·잔액/한도 부족·PIN 오류 흐름을 확인 |
| 4 | 에이전트 역할·상태 | 아래 역할표와 입력·되묻기·진행·조회 결과·근거·승인 요청·오류 상태 정의 | 질문별 담당과 다음 행동이 명확하고 기존 구현과의 차이를 기록 |
| 5 | AI 상담 화면 | 선택한 3번 기준, 질문 예시·대화·진행 표시·조회 결과·상품 근거·이체 확인 진입 | 계좌 조회·상품 질문·이체 요청의 세 시나리오를 데모로 재현 |
| 6 | 모바일 흐름 점검 | 키보드·고정 버튼 간격, 뒤로 가기, 재진입, 데모 상태 초기화 | 핵심 시연을 막는 오류를 수정하고 화면 구성 완료를 기록 |

### 에이전트 구성 기준

기존 구조를 기준으로 현재 코드와 대조하여 필요한 부분만 보완합니다. 아래 항목은 완료 체크가 아닌 다음 작업입니다.

| 구성 | 역할 | 확인할 기준 |
|---|---|---|
| 라우터 | 질문에 따라 계좌·카드·상품 담당 선택, 복합 요청의 처리 순서 결정 | 담당을 불필요하게 늘리지 않고 처리할 수 없는 요청을 안내 |
| 계좌 Agent | 계좌·거래·지출 조회, 이체에 필요한 정보 되묻기, 승인 요청 생성 | 수취 계좌·출금 계좌·금액이 정해진 뒤 확인 단계로 이동 |
| 카드 Agent | 카드 정보·한도·이용내역 안내, 정지·분실 등 관리 흐름 | 기존 기능 범위와 확인이 필요한 행동을 구분 |
| 상품 Agent + RAG | 상품 조건·금리·약관 질문과 근거 제시 | 근거 없는 답을 만들지 않고 자료 없음·조회 오류를 구분 |
| 사용자 승인 화면 | 이체 내용 확인·PIN 입력·취소·결과 표시 | PIN 입력은 채팅 밖에서 처리하고 Agent가 대신 승인하지 않음 |

- 대표 질문: “내 계좌 얼마 있어?”, “이번 달 편의점에서 얼마 썼어?”, “스타크 자유적금 우대금리 조건은?”, “토니에게 5만 원 보내줘”.
- 대화 상태: 초기 → 입력 → 처리 중 → 답변 또는 되묻기 → 확인 필요 → 사용자 승인/취소 → 결과.
- 화면 구성 단계에서는 준비된 데모 대화·결과를 사용해 흐름을 확인할 수 있습니다. 데모 응답을 실제 모델·도구 실행 결과로 기록하지 않습니다.
- 나중에 API를 연결할 때 확인 내용은 서버가 검증한 승인 정보로 대체하고, 완료는 서버 실행 성공 이후에만 표시합니다.
- 홈에 승인 대기 목록을 다시 추가하지 않습니다. 실제 연결 단계에서 취소·이탈·만료·결과 불명 처리와 서버 요청 수명주기를 맞춥니다.

### 1차 완료 시연

데모 로그인 → 홈 총자산 확인 → 계좌·거래내역 조회 → 일반 이체 흐름 → AI 상담에서 계좌 질문·상품 질문 → AI 이체 요청 → 부족한 정보 답변 → 확인·PIN 화면 → 데모 결과.

이 시연이 데모 데이터로 이어지면 **은행 앱·에이전트 구성 1차 완료**입니다. 실제 API·실모델 통합 검증과 배포 완료는 별도로 기록합니다.

## 다음에도 유지할 선택

- 상품은 1번, AI 상담은 3번, 전체 메뉴는 2번, 계좌는 3번입니다.
- 카드는 1번·3번 보기 방식을 선택할 수 있게 하는 방향입니다. 카드 혜택 메뉴도 필요합니다.
- 이체 최신 기준은 **39~43번**입니다. 받는 계좌 → 금액 → 확인 → 6자리 PIN → 완료 흐름이며 상단 로고는 없고 은행명 옆 작은 로고는 유지합니다.
- 크림·화이트·네이비, 입출금 블루 / 예적금 세이지 / 최근 거래 앰버, 좌우 약 24px, 잔액 오른쪽 정렬을 유지합니다.
- 음성 입력, 주변 카드 혜택 추천, 팀원 은행 간 이체는 현재 화면에 임의로 추가하지 않습니다.
- 상세 선택과 최신 이미지 링크는 [HANDOFF.md](HANDOFF.md)를 기준으로 봅니다. 작업 우선순위는 이 문서의 2026-11-09 지시를 적용합니다.

## 저장·Git 작업 방식

- 선택·미선택 시안과 수정본을 모두 이 `docs/design-drafts/` 폴더에 의미 있는 파일명으로 보관합니다.
- 기존 파일을 덮어쓰지 말고 수정본과 선택 기록을 추가합니다.
- 변경은 별도 브랜치에서 커밋하고 PR로 올립니다. PR #26은 시안 43개·결정·인계 문서를 보관한 병합 기록입니다.
- 새 PR의 병합은 사용자가 요청했을 때 진행합니다. 앱 코드가 바뀌는 구현 단계에서는 관련 테스트를 실행합니다.
- PR은 기능 묶음으로 나누고, 검증은 변경 범위에 맞게 합니다. 단순 UI 조정마다 전체 설계를 다시 검토하지 않습니다. 승인·권한·돈 처리 변경은 해당 동작을 집중 확인합니다.
- 각 단계가 끝나면 완료 항목·데모/실제 동작 여부·남은 막힘을 이 문서에 갱신합니다.
