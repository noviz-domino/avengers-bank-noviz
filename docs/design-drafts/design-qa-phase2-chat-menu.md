# 2단계 AI 상담·전체 메뉴 UI 확인

2026-11-09, 기준 시안 20·25와 HANDOFF.md를 확인했다.

## 반영

- AI 상담은 공통 머리글·제목·섹션·아이콘·버튼을 사용한다. 기존 SSE·승인·세션 처리를 유지했다.
- 입력창과 보내기 버튼을 둥근 공통 스타일로 맞추고 하단 메뉴 위에 유지한다. PIN 입력 위치 안내와 실제 지원 질문을 표시한다.
- 전체 메뉴는 은행 업무 / 내 정보·보안 / 설정·안내를 네이티브 `details`로 접고 펼친다. 각 그룹은 키보드로도 조작할 수 있다.
- 은행 업무에 계좌·이체·검색·상품·카드·AI·예산 가드 목적지를 연결했다.
- PIN 설정 오류를 각 입력과 `aria-describedby`·`aria-invalid`로 연결한다. 비밀번호 오류는 해당 입력 바로 아래에 표시하며 첫 오류로 포커스를 이동한다.
- 검색·가입 화면의 공통 머리글과 제목을 맞추고, 가입 필드 오류에도 `aria-invalid`를 갱신한다. 검색·가입 검증 규칙과 API 요청은 유지했다.

## 검증 및 스크린샷

실제 API(8000), 프런트(8011), Chrome CDP로 캡처했다. 로컬 폴더 `C:/Users/USER/AppData/Local/Temp/capbank-phase2/`의 다음 이미지를 생성했다. 주요 화면은 이미지를 직접 열어 시안과 비교했다.

| 캡처 | 상태 |
|---|---|
| `login-390.png` | 로그인·데모·가입 진입 |
| `chat-390.png`, `chat-320.png` | 질문 그룹·작성창·하단 탭 |
| `menu-390.png`, `menu-320.png` | 메뉴 그룹과 접힌 은행 업무 |
| `menu-pin-errors-390.png` | 빈 PIN 제출 후 비밀번호·PIN 인라인 오류 |
| `search-320.png` | 검색 폼 |

모든 캡처의 문서 폭이 320/390px 뷰포트를 넘지 않았다. 표시된 버튼·입력·선택·그룹 제목 높이 44px 이상을 검사했다. 메뉴를 닫은 뒤 자식 콘텐츠의 `checkVisibility()`가 false임을 확인했다. `node --test frontend/*.test.mjs` 21개가 통과했다.

## 차이 및 미검증

시안의 메뉴 검색·비밀번호 변경·대화 내역·음성 입력은 연결된 기능이 없으므로 추가하지 않았다. 실제 있는 목적지와 정보만 표시한다. 지원하는 카드·예산 질문은 기존 기능에 맞춰 유지했다.

이 개별 QA에서는 실제 Gemini 답변·가입 요청·PIN 변경 요청을 전송하지 않았다. 해당 흐름의 전체 통합 점검과 실제 모바일 키보드·스크린리더 확인은 별도다. 로컬 캡처 파일은 저장소에 포함하지 않았다.
