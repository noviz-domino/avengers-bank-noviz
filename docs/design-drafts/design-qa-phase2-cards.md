# 2단계 카드 화면 디자인 점검

2026-11-09 · 기준: [21 크게 보기](21-cards-option-1.png), [23 목록 보기](23-cards-option-3.png), 공통 `ui.mjs` / `ui.css`.

## 반영

- 공통 머리글·본문 제목·로딩/빈 상태/오류 안내를 재사용하고 카드 내부 이벤트가 앱 라우팅으로 전파되지 않게 했다. 기존 API와 카드 액션 식별자는 유지했다.
- 제목 26px, 본문 15px, 보조 글자 13px, 크림 패널과 블루/세이지 계열을 공통 토큰으로 맞췄다. 모든 버튼의 최소 터치 영역은 44px이다.
- 카드 목록의 긴 이름은 줄바꿈하고 실제 카드 그림 안의 이름은 두 줄로 제한한다. 전체 이름은 그림 아래 또는 목록에 계속 표시한다. 연결 계좌 번호는 공통 마스킹을 사용한다.
- 320px 거래 행은 금액을 다음 줄 오른쪽에 표시한다. 보기 전환·카드 선택은 기존 동작과 키보드 초점을 유지한다.

## 실제 화면 확인

Chrome headless CDP에서 현재 로컬 API에 데모 로그인한 뒤, 정지·분실·발급 실행 없이 확인했다. 390px 크게 보기/목록 보기, 320px 목록 보기를 캡처하고 기준 PNG와 직접 비교했다. 크림 이용 요약, 네이비 카드, 목록 선택 표시와 정보 계층을 확인했다. 기준 PNG의 그림을 그대로 복제한 것은 아니며 기존 SVG 카드 그림을 유지했다. 데모 데이터는 체크카드 두 장, 이달 거래 없음이므로 기준의 금액·거래 예시와 다르다. 빈 이용내역 상태도 실제 화면에서 확인했다.

세 화면 모두 문서 너비가 뷰포트 너비와 같았고, 보이는 버튼·링크에 44px 미만 높이는 없었다. 전체 페이지 캡처에 고정 탭이 중간에 보이는 것은 뷰포트 위치에서 캡처되기 때문이다.

로컬 캡처: `%TEMP%/capbank-phase2/cards-large-390.png`, `cards-list-390.png`, `cards-list-320.png`. 캡처는 임시 QA 자료로 저장했으며 저장소에 추가하지 않았다.
