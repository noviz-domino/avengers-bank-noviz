# 모바일 은행 앱 디자인 인계

마지막 업데이트: 2026-11-08 (Asia/Seoul)

## 현재 작업 단계

캡아메리카뱅크 백엔드를 바탕으로 **모바일 화면 시안을 정리 중**입니다. 프론트엔드 구현·API 연결은 아직 시작하지 않았습니다. 사용자는 구현보다 디자인 정리를 먼저 진행하기로 했습니다.

이 폴더에는 선택하지 않은 안과 중간 수정본까지 생성 순서대로 **43개 PNG**를 보관했습니다. 파일 번호는 시안 선택 번호가 아닙니다. 원본 생성 ID와 SHA-256은 [manifest.json](manifest.json), 전체 과정은 [README.md](README.md)에 있습니다. `references/`는 공식 사이트에서 받은 참고 이미지로 생성 시안 43개와 별도입니다.

## 공통 디자인 결정

- 모바일 중심. 시안 기준 화면 폭 390px, 좌우 여백 약 24px. 긴 홈은 자연스럽게 스크롤합니다.
- 크림색·화이트·네이비가 중심. 큰 면적을 강한 파란색으로 채우지 않습니다.
- 작은 방패 로고(별 + 빨간 줄)를 사용합니다. 입출금은 차분한 블루, 예금·적금은 세이지 그린, 최근 거래는 앰버로 제목과 아이콘을 구분합니다.
- 계좌명·번호는 왼쪽, 잔액은 오른쪽에 정렬합니다. 이체 버튼은 잔액 아래 같은 오른쪽 끝선에 맞춥니다.
- 총자산 숨김은 오른쪽 위의 작은 눈 아이콘으로 표시합니다. 별도 문구 줄로 공간을 차지하지 않습니다.
- 이체 화면 **상단 내비게이션에는 로고를 넣지 않습니다.** 받는 은행명 옆에는 은행 구분용 로고를 약 16~18px로 작게 유지합니다. 이체 최신본은 39~43입니다.
- 시안의 금액·사람·계좌·이벤트는 데모입니다. 이미지 생성에 따른 글자·요일 오류는 실제 구현에서 데이터와 맞춰 바로잡아야 합니다.

## 홈과 상품

- 홈은 당행 자산만 대상으로 총자산과 입출금·예금/적금의 접기·펼치기 목록을 제공합니다. 접힌 상태에도 개수와 합계는 보입니다.
- 총자산 아래 오픈 기념 / 신규가입 이벤트 배너 두 장을 하나의 고정 영역에서 전환합니다. 옆 배너 미리 노출과 동그란 페이지 표시는 제거합니다. 페이지 수·재생/정지는 이미지 안에 작게 겹칩니다.
- 최근 거래와 작은 AI 상담 진입 영역을 포함합니다. AI는 지출 조회·상품 질의 등을 지원하며 예산 관리가 구현된 것으로 표현하지 않습니다.
- 상품은 15번의 대표 상품 + 다른 상품 목록 구성. 레포의 실제 데모 상품명·금리를 사용합니다. 최고 금리는 우대조건·세전 여부와 함께 표시합니다.

## 카드

- 크게 보기와 목록 보기를 사용자가 선택하는 방향입니다. 카드 선택 부분만 달리하고 이용금액·이용내역·관리 기능은 일관되게 유지합니다. 기본값·전환 위치·설정 저장 방식은 추가로 확정해야 합니다.
- 자주 쓰는 **카드 혜택** 메뉴를 추가합니다. 제안 배치는 이용내역 / 카드 혜택 / 카드 관리이며 한도 확인의 최종 진입 위치는 후속 정리합니다.
- 현재 백엔드는 상품별 혜택 설명을 제공합니다. 실제 할인액·남은 혜택 집계가 구현된 것으로 가정하지 않습니다. 월 이용금액과 신용 미결제 사용액도 구분해야 합니다.

## 계좌와 이체

- 계좌 화면은 잔액·이체·거래내역 중심으로, 29번의 하단 고정 이체 버튼을 유지합니다. 상품명·개설일·금리·한도와 별칭 변경·해지는 상단 관리에 모읍니다.
- 이체는 받는 계좌 → 금액 → 내용 확인 → 6자리 PIN → 결과의 순서입니다. 승인 전에는 돈이 움직이지 않습니다.
- 사용자는 **이체를 그 순간의 흐름에서만 처리**하고 취소·이탈·실패 시 종료하길 원합니다. 홈에 승인 대기 목록을 유지하지 않습니다. 현재 백엔드의 승인 대기 레코드와 취소·만료 수명주기를 맞추는 별도 검토가 필요합니다.
- 실행 요청 이후 통신이 끊겨 결과를 모르면 실제 처리 여부를 먼저 확인해야 합니다. 임의로 재송금하거나 성공을 먼저 표시하지 않습니다.
- 예시 흐름: 생활비 통장 2,350,000원에서 토니에게 50,000원, 메모 식사비. 완료 잔액 2,300,000원. 확인 내용은 서버 승인 summary 등 검증 결과에 근거해야 합니다. 클라이언트가 승인 직전 payload를 바꿀 수 있게 만들지 않습니다.
- 토스 참조는 공식 소개의 질문 중심 계층과 여백을 적용한 것이며 최신 토스의 모든 단계를 캡처해 복제한 것은 아닙니다. 카카오페이 참고 이미지는 2023년 공식 가이드입니다. 출처는 이력 README에 있습니다.

## 추가 아이디어 — 현재 배치·구현 미정

- **음성 입력:** AI 상담에 텍스트와 함께 제공하는 아이디어. 지금은 계획에만 두며 마이크를 시안에 추가하지 않습니다.
- **주변 카드 혜택:** 사용자 위치로 보유 카드 혜택이 가능한 매장을 찾거나 추천. 배치 미정. 위치 없이 지역 검색하는 방안과 매장·혜택 조건 데이터 확보를 검토합니다.
- **다른 팀원 은행 간 이체:** 향후 팀원 은행을 등록하여 이체를 시험할 계획. 고정된 받는 은행 표시를 은행 선택으로 확장할 수 있게 고려합니다. 은행 식별자·인증·수취 확인·처리 결과·중복 요청 규약은 아직 정해지지 않았습니다.

## 이어서 할 작업

**첫 작업과 권장 진행 순서·완료 기준은 [NEXT_STEPS.md](NEXT_STEPS.md)에 정리했습니다.** 다른 컴퓨터에서 쓸 시작 문구도 포함되어 있습니다.

1. 사용자가 고른 화면의 미반영 수정부터 정리: 홈 승인 대기 삭제, 계좌 정보 진입을 관리로 통합, 카드 보기 방식·혜택 메뉴.
2. 로그인·회원가입·PIN 등록/변경, 계좌 관리, 예·적금 상세·가입, 상품 상세, 카드 혜택·관리 등 필요한 하위 화면의 디자인을 정리합니다.
3. 이체 처리 중·실패·결과 불명·잔액/한도 부족·잘못된 PIN·잠금 및 빈 상태를 설계합니다. 금액 키패드와 실제 모바일 키보드·고정 버튼 간격도 검토합니다.
4. 시안이 정리된 후 프론트엔드 구현·API 연결로 진행합니다. 아직 구현을 시작하라는 사용자 지시는 없습니다.

## 다른 컴퓨터에서 이어가기

레포를 clone하거나 기존 checkout에서 최신 main을 pull한 뒤 이 문서부터 읽습니다. 이미지와 결정 기록은 이 레포 안에 모두 포함되어 있으므로 Codex 생성 이미지 원본 폴더가 없어도 이어갈 수 있습니다.

이번 PC에서는 Python 3.11만 확인됐으며 uv·Docker는 확인되지 않았습니다. 백엔드는 Python 3.13 이상을 요구합니다. 서버 실행은 레포 루트 README의 Docker/uv 안내를 따릅니다. `.env`·API 키·다른 PC의 DB는 이 디자인 기록에 포함하지 않습니다. 이번 작업에서는 앱 실행과 백엔드 테스트를 수행하지 않았습니다.
