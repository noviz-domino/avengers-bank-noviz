## 과제 개요

자주 사용하는 은행 앱을 참고하여 **은행 모바일 웹서비스**를 구현한다.

- 기능, 이용 흐름, DB는 **함께 기획**하고, 코드는 **각자 작성**한다.
- 기능 구현 순서를 함께 정하고, 매일 아침 진행 상황을 공유하며 계획을 조정한다.

### 필수 구현 범위

| 범위 | 내용 |
|---|---|
| 은행 기본 기능 | 계좌, 카드 등. 계좌 생성은 상품별 금리와 **가입 조건** 등 실제 은행의 기능과 UI를 참고 |
| 회원가입 및 인증 | 회원가입, 로그인·로그아웃. 인증된 사용자는 본인에게 허용된 정보와 기능만 이용 |
| 자연어 입력 | 모든 기능을 자연어로 요청하면 직접 처리하거나 해당 화면 링크 제공. 대화 맥락 유지, 정보가 부족하면 추가 질문 |
| RAG | 지난 미니 프로젝트의 RAG 기능을 자연어 입력에 포함 |

| 회고 | 배운 점, 어려웠던 점과 해결 과정, 남은 한계와 개선하고 싶은 점 |

## 요구사항 대비 현황

기획과 현재 코드·DB를 맞춰 본 결과입니다. 빈칸은 구현하면서 채웁니다.

| 필수 범위 | 기획 | DB (`docs/ERD.md`) | 비고 |
|---|---|---|---|
| 회원가입·인증 | ✅ 기능 트리, 흐름 ① | ✅ `users` | 로그인 5회 실패 잠금은 DB 컬럼 없음 |
| 계좌·이체 | ✅ 명세, 흐름 ②③ | ✅ 계좌 3종 + 거래내역 | 거래내역에 메모·카테고리·거래 후 잔액 없음 → 검색·지출 통계 불가 |
| 상품 가입 조건 | ✅ 명세(예·적금 1번) | ⚠️ 금리만 있음 | 가입 기간, 최소·최대 금액, 조건 컬럼 필요 |
| 카드 | ✅ 명세, 흐름 ④ | ✅ 카드 2종 + 사용내역 | 카드 상태(정지·분실)와 한도 컬럼 없음 |
| 대출 | ✅ 명세 16개 중 9개, 흐름 ⑤ | ❌ 테이블 없음 | 가볍게 구현 ([scope.md](scope.md)) |
| 수취인·자동이체·알림 | ✅ 명세 | ❌ 테이블 없음 | |
| 자연어 입력 | ⚠️ 흐름 ⑥만 있음, 기능 명세 없음 | ❌ 대화 기록 테이블 없음 | 맥락 유지에 필요 |
| RAG | ⚠️ 흐름 ⑥만 있음 | ❌ | 문서는 벡터 DB에 따로 저장 예정 |
| **예산 관리** (추가 기능) | ✅ budget.md, 흐름 ⑦⑧ | ❌ 테이블 없음 | 거래내역·카드 사용내역에 카테고리와 거래 종류 필요 |
