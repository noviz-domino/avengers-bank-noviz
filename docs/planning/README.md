## 과제 개요

자주 사용하는 은행 앱을 참고하여 **은행 모바일 웹서비스**를 구현한다.

- 기능, 이용 흐름, DB는 **함께 기획**하고, 코드는 **각자 작성**한다.
- 기능 구현 순서를 함께 정하고, 매일 아침 진행 상황을 공유하며 계획을 조정한다.

### 필수 구현 범위

| 범위 | 내용 |
|---|---|
| 은행 기본 기능 | 계좌, 카드 등. 계좌 생성은 상품별 금리와 **가입 조건** 등 실제 은행의 기능과 UI를 참고 |
| 회원가입 및 인증 | 회원가입, 로그인·로그아웃. 인증된 사용자는 본인에게 허용된 정보와 기능만 이용 |
| 자연어 입력 | 모든 기능을 자연어로 요청하면 직접 처리하거나 해당 화면 링크 제공. 대화 맥락 유지, 정보가 부족하면 추가 질문 |
| RAG | 지난 미니 프로젝트의 RAG 기능을 자연어 입력에 포함 |

## 요구사항 대비 현황

기획과 현재 코드·DB를 맞춰 본 결과입니다. 빈칸은 구현하면서 채웁니다.

**모바일 앱**(`/app`, [ADR 0020](../decisions/0020-mobile-app-real-api.md))은 아래 표의 서버 기능을 **실제 API**로 씁니다: 로그인·회원가입·세션 유지, 총자산·계좌 상세(예·적금 금리·만기)·거래내역·별칭·해지, 거래 검색과 합계, 이체(공통 PIN 승인 창), 카드 발급·이용내역·한도·정지·분실·정지 해제(PIN), 상품 목록·상세·가입(예금은 PIN 승인), AI 상담(실시간 스트리밍, 이체는 승인 대기 → PIN 창), 거래 PIN 설정·변경. 남은 일은 배포입니다([다음 작업](../design-drafts/NEXT_STEPS.md)).

화면 표현은 [ADR 0021](../decisions/0021-ui-components.md)에 따라 공통 UI 부품으로 맞춥니다. 여백 줄이기·AI 상담 채팅형·로그인 다시 디자인은 [ADR 0027](../decisions/0027-compact-layout-chat-login.md), 전/후 화면은 [버전별 캡처](../design-drafts/implemented/README.md)에 있습니다. 간편 로그인(Google·네이버)은 화면 자리만 있고 미구현입니다. 1단계는 홈과 하단 5개 탭(홈·상품·AI 상담·카드·전체), 계좌번호 가림·토글 포커스 유지이며 나머지 화면은 2단계에 이관합니다.

| 상품 가입 조건 | ✅ 명세(예·적금 1번) | ✅ 기간·금액·나이·조건·우대(`product_preferential_rates`)·특판 | ✅ 상품 목록·상세 API, 데모 상품 seed. 가입 조건 검사는 계좌 개설 PR |
