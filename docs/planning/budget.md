# 예산 관리

> **월급날까지 "자유롭게 쓸 수 있는 돈"을 계속 계산하고, 그 돈을 넘는 결제는 사용자가 확인해야만 실행한다.**

이 프로젝트만의 차별 기능입니다. 결정 이유: [ADR 0002](../decisions/0002-budget-guard-and-scope.md)

## 한눈에 보기

- **신청한 사람만** 씁니다. 처음 한 번 수입·고정 지출·목표를 입력합니다.
- 중심 숫자는 하나, **자유 사용 가능액**입니다. 화면, 결제 검사, AI 조언이 모두 이 숫자를 씁니다.
- 결제(체크카드·신용카드·계좌 이체)가 이 숫자를 넘으면 **멈추고 이유를 보여준 뒤, 사용자가 확인해야 진행**합니다.
- 둘째 달부터는 **실제 거래내역(최근 1·3·6개월)을 분석**해서 예산 조정을 제안합니다. 바꾸는 건 항상 사용자 승인 후입니다.
- **계산은 코드, 설명과 제안은 AI**가 합니다. AI는 숫자를 만들지 않습니다.

## 중심 숫자: 자유 사용 가능액

```
자유 사용 가능액 = 남은 돈
                - 아직 안 낸 고정 지출        (월세, 공과금 …)
                - 남은 기간의 필수 생활비      (필수 카테고리 하루 중앙값 × 남은 일수)
                - 이번 주기 목표 저축 중 아직 안 모은 금액
```

- **남은 돈** = 이번 주기 수입 - 이번 주기에 쓴 돈 (신용카드 포함)
- 마이너스가 되면 **여유 없음 경고**를 띄웁니다.

## 규칙

| # | 규칙 | 이유 |
|---|---|---|
| 1 | **주기는 월급날부터 다음 월급날 전날까지** | 달력 기준이면 월급 전후로 돈이 몰리거나 모자랍니다 |
| 2 | **모든 지출은 쓴 주기에서 한 번만 차감**. 신용카드도 쓴 순간 차감하고 "청구 예정"으로 묶어 둡니다. 카드 대금이 실제로 빠질 때는 다시 차감하지 않습니다 | 같은 돈을 두 번 빼지 않기 위해. 카드 결제일이 월급날 전이든 후든 똑같이 동작합니다 |
| 3 | **고정 지출 목록에 "카드값"을 넣지 않습니다** | 규칙 2로 이미 반영됩니다 |
| 4 | **필수 생활비 = 필수 카테고리(식비·교통·의료)의 하루 중앙값 × 남은 일수** | 평균은 회식 한 번에 크게 부풀어서 중앙값을 씁니다 |
| 5 | **목표 저축액은 주기마다 다시 계산**: 남은 목표 금액 ÷ 남은 주기 수 | 못 모은 달이 있으면 다음 달에 자동으로 나눠 반영 |
| 6 | **결제 검사 대상은 체크카드, 신용카드, 계좌 이체 전부** | 충동구매는 송금으로도 합니다 |
| 7 | **예산 변경은 제안만, 반영은 사용자 승인 후** | 분석 결과로 예산이 마음대로 바뀌면 안 됩니다 |

## 예시

### 평소: 여유가 있을 때

월급 300만 원, 주기 시작일(월급날)

```
이번 주기 수입                 300만
  고정 지출 (월세·공과금·통신)   -200만
  목표 저축 (휴대폰)             -25만
  필수 생활비 (30일)             -20만
──────────────────────────────────
자유 사용 가능액                 55만
```

충동구매 30만 원 → 55만 이내라 **통과**. 결제 후 자유 사용 가능액 25만.

### 부족: 7일 만에 200만 원을 썼을 때

```
남은 돈                                100만
  아직 안 낸 고정 지출 (월세·공과금)      -75만
  필수 생활비 (식비 1.5만 + 교통 0.4만) × 23일  -43.7만
  목표 저축 (휴대폰)                     -25만
──────────────────────────────────────────
자유 사용 가능액                        -43.7만  ⚠️ 여유 없음
```

사용자에게 보여주는 것:

```
⚠️ 이번 주기에는 여유가 없어요. 지금 속도면 월급날 전에 약 44만 원이 부족해요.

  ① 휴대폰 저축을 이번 달만 쉬기       → 부족분 18.7만 (목표일 1개월 늦어짐)
  ② 식비를 하루 1.5만 → 1만으로 줄이기 → 부족분 32.2만 (0.5만 × 23일 = 11.5만 절약)
  ③ 둘 다                             → 부족분 7.2만

  허리띠 모드: 월세·공과금을 빼면 하루 1.1만 원으로 지내야 해요.
```

어떤 걸 고를지는 **사용자가 정합니다**. 고른 내용은 이번 주기 계획에 반영됩니다.

## 결제 검사

| 상황 | 결과 | 응답 |
|---|---|---|
| 결제 금액 ≤ 자유 사용 가능액 | **통과** | 그대로 결제 |
| 결제 금액 > 자유 사용 가능액 | **확인 요청** | `409 BUDGET_CONFIRMATION_REQUIRED` + 영향 설명 ("이 결제를 하면 월세 낼 돈이 부족해져요", "휴대폰 목표가 2개월 늦어져요") |
| 확인 요청 후 사용자가 **사유를 적고 확인** | **결제** | 사유와 결정을 기록 |
| 필수 업종 (의료·약국) | **항상 통과** | 자유 사용 가능액이 마이너스여도 결제. 기록만 남김 |
| 예산 관리를 신청하지 않은 사람 | 검사 안 함 | 일반 결제 |

- 잔액 검사와 예산 검사는 **같은 트랜잭션 안**에서 합니다. 결제 두 건이 동시에 와도 둘 다 통과하지 않게 행을 잠급니다.
- 같은 결제의 확인 요청이 두 번 와도 **한 번만 결제**되게 멱등키를 씁니다.

## 이용 단계

| 단계 | 언제 | 무엇을 |
|---|---|---|
| ① 신청 | 처음 한 번 | 월 수입, 월급날, 고정 지출(이름·금액·나가는 날), 필수 카테고리. AI가 대화로 받고 표로 정리 → **사용자 확인 후 저장** |
| ② 목표 등록 | 원할 때 | "6개월 뒤 휴대폰". 가격은 AI가 추정 → **사용자가 확정** → 매달 저축액 계산 |
| ③ 주기 시작 | 매 월급날 | 목표 저축액을 **적금 계좌로 자동이체**, 이번 주기 계획 생성 |
| ④ 결제할 때 | 매 결제 | 결제 검사 (위 표) |
| ⑤ 여유 없을 때 | 자유 사용 가능액 < 0 | 경고 + 선택지 + 허리띠 모드 |
| ⑥ 분석·조언 | 주기 끝 / 요청 시 | 소비 패턴 분석, 예산 조정 제안 |

## 소비 패턴 분석 (둘째 달부터)

### 분석 기간

| 쌓인 데이터 | 기준 |
|---|---|
| 1개월 미만 | 처음 입력한 값 |
| 1~2개월 | 지난 주기 + "데이터가 적어 정확도 낮음" 표시 |
| 3~5개월 | 최근 3개월 |
| 6개월 이상 | 최근 3개월과 6개월 비교 (추세) |

### 찾아내는 것

| 분석 | 조언 예시 |
|---|---|
| 입력값과 실제의 차이 | "교통비를 10만 원으로 적으셨는데 최근 3개월 평균은 14만 원이에요. 예산을 고칠까요?" |
| 카테고리별 추세 | "외식비가 3개월 연속 늘고 있어요 (12만 → 15만 → 19만)" |
| 평소보다 튀는 주기 | "이번 달 쇼핑이 평소의 2배예요" |
| 숨은 고정 지출 | "매달 13일에 13,500원이 나가요. 고정 지출에 추가할까요?" (같은 가맹점, 비슷한 금액, 매달 반복) |
| 목표 달성 예측 | "지금 추세면 휴대폰 목표가 1개월 늦어져요" |
| 다음 주기 예측 | 고정 지출 + 필수 생활비 + 선택 지출 중앙값 |

## AI가 하는 일과 하지 않는 일

| AI가 한다 | AI가 하지 않는다 |
|---|---|
| 신청할 때 대화로 수입·지출 받기 → 표로 정리 | 저장 (사용자 확인 후 코드가 저장) |
| 목표 상품 가격 추정 | 가격 확정 (사용자가 확정) |
| 분석 결과와 결제 영향을 **사람 말로 설명** | 평균·추세·남은 금액 **계산** (코드가 계산해서 넘겨줌) |
| 조정안 제안 | 예산 변경 (사용자 승인 후 코드가 변경) |
| 가맹점 카테고리 분류 (규칙으로 안 되는 것만) | — (사용자가 고칠 수 있음) |

## 필요한 데이터 (초안)

| 테이블 | 주요 컬럼 |
|---|---|
| `budget_profiles` | user_id, 월 수입, 월급날, 모드, 신청일 |
| `fixed_expenses` | user_id, 이름, 금액, 나가는 날, 카테고리 |
| `savings_goals` | user_id, 이름, 목표 금액, 목표일, 연결 적금 계좌, 상태 |
| `budget_cycles` | user_id, 시작일, 종료일, 수입, 이번 주기 목표 저축액, 선택한 조정안 |
| `budget_decisions` | 결제 시도마다: 금액, 결제 수단, 자유 사용 가능액, 결과(통과·확인 요청·예외), 사용자 사유 |
| `categories` | 이름, 필수 여부 |

그리고 기존 테이블에 추가할 것:
- 거래내역·카드 사용내역에 **카테고리** (지금 ERD에 없음)
- 신용카드 사용내역에 **청구 예정 / 청구 완료** 상태

컬럼은 구현할 때 확정하고 `docs/ERD.md`에 반영합니다.

## 결정 대기

추천안으로 기획했고, 구현 전에 다시 확인합니다.

| 항목 | 추천안 | 다른 안 |
|---|---|---|
| 예산 초과 시 방식 | **확인 모드 하나로 시작** | 알림 모드(결제는 되고 안내만), 잠금 모드(24시간 대기) 추가 |
| 목표 저축 | **실제 적금 계좌로 월급날 자동이체** | 예산에서 떼어두기만(가상) |
| 검사 대상 | **체크카드, 신용카드, 계좌 이체** | 카드만 |
| 데모 데이터 | **6개월치 가상 거래 seed** | 없음 (데모에서 분석 화면이 비어 있음) |

## 범위 밖

- 카드사별 이용 기간(결제일마다 청구되는 사용 기간)에 따른 청구일 계산. 처음에는 "청구 예정 총액"만 보여줍니다.
- 수입이 불규칙한 사람(프리랜서 등)의 주기.
- 여러 사람이 같이 쓰는 예산(가족·커플).
