# 예산 관리와 결제 가드

**AI가 돈을 계산하거나 결제를 허락하지 않는다. 서버가 계산하고, 사람이 사유와 PIN으로 확인한다.** [ADR 0024](../decisions/0024-budget-guard.md)

## 코드 위치

| 파일 | 역할 |
|---|---|
| `domains/budget/calc.py` | 월급 주기, 고정 지출 날짜, 생활비 예약, 목표 저축, 자유 사용 가능액 |
| `domains/budget/service.py` | 거래 합계, 신청·조회·변경·해지, 주기 잠금, 승인 전 설정 스냅샷 |
| `domains/accounts/money.py` | 타인 이체 실행 직전 재검사 |
| `domains/cards/service.py` | 체크·신용카드 모두 검사, 초과 시 결제 대신 승인 대기 생성 |
| `domains/approvals/service.py` | PIN 검증, 예산 변경/해지/결제 실행, 사유·긴급 기록 |
| `frontend/budget.mjs` | 신청 폼 → 내용 확인 → 저장 또는 PIN 승인 → 서버 계산 내역 |

## 요청 흐름과 핵심 규칙

1. `GET /budget`는 미신청이면 `enrolled:false`, 신청했으면 생활비만 본 금액과 저축까지 지킨 금액을 함께 준다. AI의 `get_budget`도 같은 API를 쓴다.
2. 카드 결제는 카드 → 예산 주기 → 계좌 순서로 잠근다. 신용카드는 잔액이 나가지 않아도 사용한 순간 지출로 센다. 대금 출금과 내부 이체는 중복으로 세지 않는다.
3. 초과 카드 결제는 돈을 쓰지 않고 `409`와 승인 번호를 준다. 이체는 기존 승인 요청에 예산 영향을 붙인다. PIN·사유는 채팅 밖의 공통 승인 창에서 받는다.
4. 실행 시 주기 잠금 안에서 다시 계산한다. 확인 때보다 상황이 악화됐으면 `BUDGET_CHANGED`로 실패한다. 사용자가 긴급을 고르면 사유와 결정을 기록한다.
5. 예산 설정 강화는 바로 반영한다. 수입 증가·목표 축소·항상 통과 업종 추가 등 제한 완화는 `202 BUDGET_UPDATE`를 만들고 PIN 후 반영한다. 그사이 다른 설정 변경이 있으면 오래된 요청을 실패시킨다.

## 왜 이렇게 했나

카드 한 장만 잠그면 서로 다른 카드나 이체가 같은 예산을 동시에 사용할 수 있다. 사용자 주기 행을 함께 잠가 공통 예산을 보호한다. 승인 payload는 서버에 저장하고 클라이언트가 바꿀 수 없게 한다. 숫자·이유·확인 시점을 같은 기록으로 남겨 승인과 실행의 차이를 추적한다.

## 검증과 한계

SQLite API 테스트 외에 실제 PostgreSQL에서 두 신용카드의 75,000원 결제를 동시에 보내 10만 원 예산에서 한 건만 즉시 처리됨을 확인했다. 브라우저에서는 신청 확인, 제한 완화 취소, PIN 해지를 확인했다. Gemini의 예산 답변도 API 숫자와 대조했다.

생활비는 업종마다 금액 + 주기(매일·주 N회·월 N회)다. 매일 항목은 `남은 일수 × 금액`, 주·월 항목은 `이번 주기 계획액 − 그 업종에서 이미 쓴 돈`을 남겨 둔다(`calc.essential_reserve`). 예전 저장값(하루 금액 숫자)은 `calc.essential`이 매일로 읽어 마이그레이션이 없다. 첫 버전은 단일 목표를 사용한다. 소비 분석·이월·자동 저축은 후속이며 실기기 키보드는 검증하지 않았다.

## 면접 예상 질문

- 신용카드는 돈이 나가지 않았는데 왜 지출인가? 쓴 순간 예산에서 예약해야 이후 대금을 낼 돈을 다시 쓰지 않기 때문이다.
- AI에게 토큰이 있는데 초과 결제를 승인할 수 없나? 승인 도구가 없으며 서버의 PIN 검증과 사용자가 입력한 사유가 필요하다.
- 승인 전에 다른 결제가 들어오면? 주기 잠금 후 다시 계산하고 확인 때보다 나빠졌으면 실패시킨다.

**Q. 외식처럼 가끔 쓰는 돈은 왜 "남은 일수 × 하루 금액"으로 계산하지 않나요?**
A. 외식 주 2번 3만 원을 하루로 나누면 8,571원인데, 이렇게 하면 월말엔 거의 안 남기고, 이번 달에 이미 외식을 다 했어도 계속 남겨 둡니다. 그래서 주·월 항목은 "이번 주기에 쓸 계획액 − 이미 쓴 돈"으로 남깁니다. 대신 매일 쓰는 식사·교통은 이미 많이 썼더라도 남은 날의 밥값이 필요하니 남은 일수만큼 남깁니다.
