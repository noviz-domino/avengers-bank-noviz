# 예산 생활비가 "매일 남겨 둘 돈"으로만 받아져 가끔 쓰는 돈을 못 넣음

- 날짜: 2026-11-12
- 상태: ✅ 해결 ([ADR 0024](../decisions/0024-budget-guard.md) "생활비를 금액 + 주기로")

## 문제

예산 신청 화면의 "하루 필수 생활비"는 업종마다 **하루 금액**만 받았고, 안내 문구는 "매일 **남겨 둘** 금액"이었습니다. 직접 써 보니:
- "남겨 둘 돈"이 아니라 "평소 **쓰는** 돈"을 적어야 하는 것 아닌가 헷갈렸습니다.
- 쇼핑·외식·의료·주거통신·여가처럼 **가끔 쓰는 돈은 하루 금액으로 환산할 수가 없었습니다**("외식은 주에 두 번 정도").

## 어떻게 알았나

사용자가 실제 화면으로 예산을 신청해 보며 발견(사용성 문제). 코드에서는 `calc.compute`가 `essentials_daily`(하루 금액의 합) × 남은 일수만 계산하고 있었습니다.

## 원인

기획(budget.md)의 생활비 모델이 "식사·교통처럼 **매일 조금씩**"만 가정했습니다. 가끔 쓰는 업종도 같은 칸에 넣게 되어 있었고, 입력 단위(하루)와 실제 소비 습관(주·월 몇 번)이 맞지 않았습니다.

## 해결

- 업종마다 **금액 + 주기**(매일 / 주 N회 / 월 N회)로 받음.
- 남겨 둘 돈: 매일 항목은 `남은 일수 × 금액`(그대로), 주·월 항목은 `이번 주기 계획액 − 그 업종에서 이미 쓴 돈`.
  - 예: 외식 주 2회 × 3만 원, 31일 주기 → 계획 265,715원. 이미 10만 원 썼으면 165,715원만 남겨 둠.
- 두 가지 계산 방식(하루 환산 vs 계획액 − 쓴 돈)을 예시 숫자와 함께 보여 드리고 고르게 함 → 계획액 − 쓴 돈.
- 저장 칸(JSON)은 그대로, 예전 값(숫자)은 "매일"로 읽어서 **마이그레이션 없이** 바꿈. API도 숫자 하나는 매일로 받음.
- "매일 1만 → 월 1회 1만"처럼 주기만 바꿔 덜 남기게 해도 PIN 승인이 필요하도록 완화 판정을 30일 기준 계획액으로 비교.
- 테스트: 계산 단위 테스트(매일·주·월, 초과 지출 시 0), 잘못된 주기·횟수 422, 신청 응답 형식, 주기 변경 완화 판정.

## 배운 점

- 계산식이 맞아도 **입력 단위가 사람의 습관과 다르면** 기능을 쓸 수 없다. "매일 얼마"보다 "한 번에 얼마 × 몇 번"이 사람이 아는 숫자다.
- 저장 형식을 바꿀 때 예전 값을 읽는 쪽에서 해석해 주면(`calc.essential`) DB 마이그레이션 없이 넘어갈 수 있다.
