# 2026-11-11 화면 다듬기 중에 생긴 문제들

로그인 화면 정리(#46), 정적 파일 캐시(#47), 레이아웃·하단 탭·검색 개편(ADR 0029), 카드 감사 기록(ADR 0030)을 하면서 부딪힌 문제입니다. 전/후 화면은 [버전별 캡처](../design-drafts/implemented/README.md)(v3 → v4)에 있습니다.

---

## 1. 배포 뒤 흰 화면 (정적 파일 캐시)

- 상태: ✅ 해결 (#47, [ADR 0028](../decisions/0028-static-no-cache.md))

**문제** 로그인 화면의 간편 로그인 버튼을 공통 부품(`ui.mjs`의 `socialButton`)으로 옮긴 뒤 화면을 열자 **앱 전체가 하얗게** 나왔습니다.

**어떻게 알았나** 브라우저 콘솔에 `The requested module './ui.mjs' does not provide an export named 'socialButton'`. 새 `login.mjs`는 받았는데 `ui.mjs`는 브라우저가 **예전 파일을 캐시에서** 꺼내 쓰고 있었습니다.

**원인** FastAPI `StaticFiles`는 `ETag`·`Last-Modified`만 붙이고 `Cache-Control`을 붙이지 않습니다. 이때 브라우저는 "마지막 수정 뒤 지난 시간의 일부" 동안 서버에 묻지 않고 캐시를 씁니다(휴리스틱 캐시). 빌드 도구 없이 파일 이름이 늘 같은 ES 모듈 앱이라, 파일 하나만 옛것이어도 `import`가 실패해 앱 전체가 멈춥니다. **배포 직후 실제 사용자에게도 똑같이 생길 문제**였습니다.

**해결** `/app` 응답에 `Cache-Control: no-cache`(쓰기 전에 서버에 확인)를 붙였습니다(`main.py`의 `RevalidatedStaticFiles`). 안 바뀌었으면 304(본문 없음)라 비용이 거의 없습니다. 헤더와 304를 지키는 테스트를 추가했습니다(`tests/test_static_cache.py`).

**배운 점** `no-cache`는 "저장 금지"가 아니라 "확인 후 사용"(저장 금지는 `no-store`). 빌드 없는 프론트엔드에서는 캐시 정책이 곧 배포 안정성이다. 그리고 이 헤더 **이전에** 캐시된 파일은 여전히 휴리스틱 캐시로 남아 있어서, 첫 배포 직후 몇 시간은 같은 일이 생길 수 있다(로컬에서 실제로 한 번 더 겪음).

## 2. 데모 카드가 어느새 분실 상태

- 상태: ✅ 해결 ([ADR 0030](../decisions/0030-card-status-audit-demo-card.md))

**문제** 카드 화면에 데모 카드가 "분실 신고" 상태로 떠 있었습니다. 언제, 누가, 어디서(화면·AI 상담·MCP 도구) 했는지 **아무도 답할 수 없었습니다.**

**어떻게 알았나** DB에서 카드 상태(`LOST`)는 확인했지만 `audit_logs`에 카드 관련 기록이 하나도 없었고, `cards`에는 수정 시각 칸도 없었습니다. 그날 통합 점검 전에 찍은 캡처에도 이미 분실 상태라 점검 탓도 아니었습니다.

**원인**
1. 카드 정지·분실·해제가 감사 기록 대상이 아니었음 (로그인 실패·PIN 설정만 기록).
2. 데모 비밀번호가 README에 공개돼 있어 **누구나 데모 카드를 분실 신고**할 수 있고, 분실은 되돌릴 수 없음. 서버 시작 seed는 로그인 잠금만 풀고 카드는 그대로 둠 → 공개 서버에서도 같은 일이 생기면 다음 방문자는 분실 카드만 보게 됨.

**해결**
- 정지·분실을 `CARD_SUSPENDED`·`CARD_LOST`로, PIN 해제를 `CARD_UNSUSPENDED`로 감사 기록. 이전 상태와 입구(`X-Requested-By`: WEB·AGENT·MCP)를 함께 남김.
- seed가 서버 시작 때 데모 사용자에게 **쓸 수 있는(분실 아닌) 카드가 없으면 새로 발급**. 분실 카드를 ACTIVE로 되돌리지 않는 이유: seed도 "분실은 되돌릴 수 없다"는 업무 규칙을 지켜야 하므로.
- 카드 화면은 처음 열 때 쓸 수 있는 카드부터 보여 줌.
- 테스트 2개: 감사 기록 순서·actor, seed가 분실 뒤 새 카드를 발급하고 이미 있으면 그대로 두는지.

**배운 점** 감사 기록은 돈이 움직일 때만이 아니라 **되돌릴 수 없는 상태 변경**에도 필요하다. "왜 이렇게 됐지?"에 답할 수 없다는 것 자체가 버그였다.

## 3. 뒤로 버튼 무한 루프

- 상태: ✅ 해결 ([ADR 0029](../decisions/0029-layout-gutter-tabs-menu.md) 결정 8)

**문제** 홈 → 거래 검색 → (뒤로) → **전체 메뉴** → (뒤로) → **거래 검색** → (뒤로) → 전체 메뉴… 홈으로 나갈 수 없었습니다.

**원인** 두 화면의 뒤로 버튼이 서로를 가리킴.
- 거래 검색의 뒤로: 원래 메뉴에서만 열려서 **"전체 메뉴로 가기"로 고정**(`ctx.go("menu")`)
- 이번에 만든 전체 메뉴의 뒤로: **"열기 전 화면으로"**(`history.back()`)
- 검색을 홈에서도 열 수 있게 되면서 고정 목적지가 틀려짐.

같은 종류의 문제가 하나 더 있었습니다. 계좌 관리에서 별칭을 저장하면 상세 화면을 새로 "열어서"(`go("account")`) 기록이 상세 → 관리 → 상세로 쌓였고, 상세의 뒤로가 관리 화면으로 돌아갔습니다.

**해결** 하단 탭이 없는 화면(전체 메뉴·검색·예산·계좌 상세·관리·이벤트)의 뒤로를 모두 하나의 `back` 액션(기록 한 칸 뒤, 기록이 없으면 홈)으로 통일. 별칭 저장 뒤에는 새로 이동하지 않고 `history.back()`으로 되돌아감. 브라우저에서 경로 5가지를 직접 눌러 확인하고, 통합 점검도 새 동작에 맞게 고침.

**배운 점** 화면이 "어디로 돌아갈지"를 각자 알고 있으면, 여는 길이 늘어날 때마다 고리가 생긴다. "돌아가기"를 `go()`(앞으로 쌓기)로 만들면 기록이 꼬인다.

## 4. 새 메뉴 버튼이 카드·상품 화면에서만 안 눌림

- 상태: ✅ 해결 ([ADR 0029](../decisions/0029-layout-gutter-tabs-menu.md))

**문제** 공통 머리글(`ui.mjs`의 `header`)에 전체 메뉴 버튼(`menu: true`)을 추가했는데, 홈·AI 상담에서는 되고 **카드·상품 화면에서만** 눌러도 반응이 없었습니다. 단위 테스트는 모두 통과한 상태였습니다.

**어떻게 알았나** 탭 5개에서 메뉴 열기 → 닫기를 자동으로 눌러 보는 브라우저 점검에서 카드 화면만 실패. 버튼 HTML을 찍어 보니 `data-action="menu"`가 `data-card-action="menu"`로 바뀌어 있었습니다.

**원인** 각 화면 모듈의 "가정"이 공통 부품 변경으로 깨짐.
- 카드 화면: 머리글 HTML에서 **첫 번째 `data-action`을 자기 것으로 바꾸는** 코드(뒤로 버튼용)가 있었는데, 첫 화면에서는 새 메뉴 버튼이 그 "첫 번째"가 됨.
- 상품 화면: 자기 영역 안의 **모든 버튼 클릭을 가로채고** 앱으로 넘기지 않음(`stopPropagation`).

**해결** 카드 화면은 뒤로 버튼이 있는 하위 화면에서만 바꾸기. 상품 화면은 `data-action` 버튼은 앱 라우팅으로 넘기기.

**배운 점** 공통 부품에 기능을 더하면 그 부품을 쓰는 쪽의 숨은 가정이 깨진다. 이런 건 단위 테스트가 아니라 **실제 화면을 눌러 보는 점검**에서 잡힌다.

## 5. 계좌 검색으로 신용카드 결제를 못 찾음

- 상태: ✅ 해결 ([ADR 0029](../decisions/0029-layout-gutter-tabs-menu.md) 결정 9)

**문제** "거래내역 검색"이 홈에 있었는데, 계좌 검색인지 카드 검색인지 애매했습니다. 확인해 보니 **계좌 장부만** 검색해서 신용카드 결제는 건마다 나오지 않았습니다.

**원인** 체크카드는 결제 즉시 계좌에서 출금돼 장부에 남지만, 신용카드는 결제일에 "카드 대금" 한 줄로만 남습니다(설계대로). 카드 사용내역은 카드 화면에서 결제일별로만 볼 수 있었고 검색이 없었습니다.

**해결** 검색을 해당 탭으로: 계좌 탭 머리글에 **계좌 검색**, 카드 탭 머리글에 **카드 검색**(새 API `GET /cards/transactions`: 가맹점·카드·카테고리·기간, 승인 합계는 취소 제외, 남의 카드 차단, 모르는 조건은 422), 전체 메뉴에 **메뉴 검색**. 홈에서는 검색 버튼을 뺌.

**막힌 점** 카드 라우터에 `/{card_id}`가 먼저 등록돼 있어서 `/cards/transactions`를 뒤에 두면 `transactions`를 카드 번호로 읽으려다 422가 남 → 새 경로를 앞에 둠.

## 6. 고르지 않은 시안이 앱 안에 숨어 있었음

- 상태: ✅ 해결 (#46, [ADR 0027](../decisions/0027-compact-layout-chat-login.md))

**문제** 로그인 시안 A·B·C 중 B를 골랐는데, A·C가 `?login=a`·`?login=c` 주소로 **실제 앱에서 열리게** 남아 있었습니다.

**원인** "고르지 않은 안도 기록으로 남긴다"는 요청을 "실행되는 코드로 남긴다"로 해석함. 그 해석이 작업 메모에 규칙처럼 저장돼 다른 작업에도 퍼질 수 있었음.

**해결** 앱에는 B만, A·C의 코드·캡처는 `docs/design-drafts/.../archived-code/`로 옮김. 이후 리뷰 중 만든 "가로 버튼 두 줄" 간편 로그인 안도 같은 방식으로 보관.

**배운 점** 고객이 쓰는 앱에 안 쓰는 화면을 숨겨 두면 관리할 것만 늘고 누구나 주소로 열 수 있다. 요구를 저장할 때 내 해석을 섞지 않는다.

## 7. 로컬 Docker Desktop이 켜지지 않음

- 상태: ✅ 해결 (개발 환경)

**문제** Docker Desktop을 실행해도 엔진이 뜨지 않아(`dockerDesktopLinuxEngine` 파이프 없음) 로컬 서버를 띄울 수 없었습니다. 전부터 "실행 직후 꺼짐, 원인 미확인"으로 남아 있던 문제입니다.

**어떻게 알았나** `%LOCALAPPDATA%\Docker\log\host\com.docker.backend.exe.log`의 마지막 오류: `rename ...\run\sailor-ingest.sock ... .stale: The file cannot be accessed by the system`. 고친 뒤 다시 켜자 같은 오류가 `docker-secrets-engine\engine.sock`에서 한 번 더 났습니다.

**원인** 이전에 Docker가 비정상 종료되며 남긴 **유닉스 소켓 파일**. Windows의 소켓 파일은 특수한 재분석 지점이라 Docker가 지우지도 이름을 바꾸지도 못해 시작에 실패.

**해결** 소켓 파일 자체는 지울 수 없어서 **들어 있는 폴더째 이름을 바꿔** 치움(`Docker\run`, `docker-secrets-engine` → `*.old-20261111`). 다시 켜자 5초 만에 엔진이 뜸.

**배운 점** "원인 미확인"으로 넘긴 환경 문제도 로그 파일 한 줄이면 풀리는 경우가 많다.

## 같이 남길 작은 것들

- **여백을 1.5배로 늘리자 계좌번호가 `110-` / `***-000001`로 끊김** → 계좌 줄의 번호를 한 줄로 고정하고 이체 버튼 여백을 줄임. 화면 폭이 좁아지면 숫자·번호 줄부터 확인할 것.
- **확인용 임시 서버 탭을 닫지 않아** 사용자가 꺼진 서버의 예전 화면(배너 이미지 깨짐, 옛 여백)을 보고 "안 바뀌었다"고 판단함 → 확인이 끝나면 임시 탭을 닫는다.
- **통합 점검이 내 실수를 잡음**: 코드 한 줄 끝에 단 주석이 이어지는 HTML 문자열까지 주석으로 만들어 검색 폼이 사라짐 → 문자열을 이어 붙이는 줄 끝에는 주석을 달지 않는다.
- **화면 확인 기준 크기**를 아이폰 크기(375×812)에서 사용자의 실제 기기인 갤럭시 S23+의 보이는 영역(384×760)으로 바꿈.
