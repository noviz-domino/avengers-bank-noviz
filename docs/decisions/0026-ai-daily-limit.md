# 0026. 서버 전체 AI 호출 하루 한도

- 상태: 채택
- 날짜: 2026-11-11
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0013](0013-agent-rag-plan.md) 사용자당 1분 한도, [ADR 0025](0025-https-caddy-duckdns.md) 서버 공개

## 배경

- 서버를 인터넷에 공개했습니다(ADR 0025). 회원가입은 누구나 할 수 있습니다.
- Gemini를 부르는 입구(`/chat` 4개, `/rag/search`, `/rag/ask`, MCP의 `/rag/ask`)는 모두 `spend_ai_calls`의 **사용자당 1분 10회** 한도를 거칩니다. 이 한도는 한 사람이 다른 사람 몫을 다 쓰지 않게 하는 **공정성** 장치일 뿐, 비용 상한은 아닙니다. 봇이 계정을 여러 개 만들면 호출량에 끝이 없습니다.

## 결정

1. `spend_ai_calls`에 **서버 전체 하루 한도**를 더합니다. 기본 100회(`AI_DAILY_LIMIT`), 한국 날짜 기준이고, 단위는 기존과 같습니다(채팅 1번 = 3, RAG 1번 = 1).
2. 넘으면 누구에게나 `429 AI_DAILY_LIMIT`을 돌려줍니다. 1분 한도(`AI_RATE_LIMITED`)를 먼저 확인하고, 거절된 요청은 어느 한도에도 세지 않습니다.
3. 채팅 화면은 429일 때 서버 안내 문구를 그대로 보여 줍니다(1분 한도와 하루 한도를 구분하기 위해).
4. 횟수는 서버 메모리에 둡니다. 재시작하면 0부터 다시 셉니다.

## 검토한 대안

| 대안 | 장점 | 단점 | 고르지 않은 이유 |
|---|---|---|---|
| 회원가입 제한(IP별·초대 코드) | 봇 계정 생성을 막음 | IP를 바꾸면 우회, 면접관도 불편 | 비용을 직접 묶지 못함 |
| 사용자당 하루 한도 | 한 계정이 다 쓰지 못함 | 계정을 늘리면 우회 | 총량이 무한함 |
| Gemini 키(Google 쪽) 한도만 | 코드 변경 없음 | 유료 키는 예산 알림만 있고 자동 차단이 없음 | 앱에서도 확실히 묶어 둠 |
| DB에 횟수 저장 | 재시작해도 유지 | 테이블·마이그레이션 추가 | 서버 한 대, 평일 낮 운영이라 과함 |

## 결과

- 좋아지는 점: 하루 비용의 최대치가 정해집니다(호출 100회). 모든 AI 입구가 한 함수를 거치므로 새 입구도 같은 한도에 걸립니다.
- 감수할 점: 봇 하나가 1분 10회로 돌면 10분 만에 그날 한도를 다 써서, 다른 사람의 AI 상담도 막힙니다(가용성보다 비용을 우선). 서버를 재시작하면 횟수가 0이 됩니다(평일 11:25 시작 때 초기화되는 셈). 서버를 여러 대로 늘리면 Redis·DB로 옮겨야 합니다.
- 팀 뼈대와의 차이: 팀 뼈대에는 AI 기능이 없습니다.

## 1분 한도를 대화 기준 6번으로 (2026-11-12)

**배경** 1분 한도는 "AI 호출 10단위"였고 상담 한 번은 3단위라, 안내는 "1분에 10번"인데 실제로는 상담 3번에서 막혔다([개발 기록](../troubleshooting/2026-11-11-ai-chat-rate-limit.md)). 실측 비용은 상담 한 번 평균 약 3.8원(최대 약 5.6원)이었다.

**결정**
- **1분 한도는 요청(대화) 수로 센다: 사용자당 1분에 6번.** 상담 한 번, RAG 검색·답변 한 번이 각각 1번이다. 안내 문구도 "1분에 6번까지"로 한도 숫자를 그대로 쓴다.
- **하루 한도(서버 전체 100)는 지금처럼 AI 호출 수로 센다**(상담 = 3). 1분 한도를 대화 기준으로 바꿔도 하루 비용 상한(상담 약 33번, 약 190원)은 변하지 않는다.

**감수할 점** 한 사람이 1분에 상담 6번(AI 호출 18번)을 쓸 수 있어 전보다 2배 빨리 하루 한도에 닿는다. 봇 하나가 연속으로 쓰면 약 6분 만에 그날 한도를 다 쓴다(전에는 약 10분). 공개 데모 계정을 함께 쓰는 문제(통합 점검과 사람이 한도를 나눠 씀)는 그대로다.
