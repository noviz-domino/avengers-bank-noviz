# 0002. 예산 관리 추가와 구현 범위 조정

- 상태: 채택 (일부 항목은 "결정 대기")
- 날짜: 2026-11-04
- 관련 PR: (이 문서를 추가하는 PR)

## 결정

1. **예산 관리 기능을 추가한다.** 월급날까지 "자유롭게 쓸 수 있는 돈"을 계산하고, 그 돈을 넘는 결제는 사용자 확인 후에만 실행한다. 명세: [budget.md](../planning/budget.md)
2. **구현 범위를 포트폴리오 기준으로 좁힌다.** 돈 처리·보안·예산 관리·자연어 Agent를 깊게, 나머지는 가볍게, **대출은 뺀다.** 범위: [scope.md](../planning/scope.md)
3. **신용카드 사용액은 쓴 순간 그 주기 예산에서 차감**하고, 카드 대금 출금 때는 다시 차감하지 않는다.

## 배경

- 이 레포는 포트폴리오로 쓴다. 팀 기획 41개를 얕게 다 만들면 이전 포트폴리오(langgraph-financial-agent)와 비슷한 "은행 Agent"로 보인다.
- 이전 프로젝트는 JSON 장부를 다뤘다. 이번에는 실제 DB·인증·트랜잭션이 있어서, **돈 처리의 정확성**과 **Agent를 실제 백엔드에 안전하게 붙이는 것**을 보여줄 수 있다.
- 차별 기능이 필요했다. 소비 분석 서비스는 많지만 대부분 **분석과 알림까지**다. 은행은 **결제 순간에 개입**할 수 있다.

## 검토한 대안

### 신용카드를 예산에 넣는 방식

| 대안 | 장점 | 단점 | 결과 |
|---|---|---|---|
| 고정 지출에 "카드값"을 적고 결제 때도 차감 | 직관적 | **같은 돈을 두 번 차감** | 버림 |

| **쓴 순간 이번 주기에서 차감하고 "청구 예정"으로 묶어 둠** | 규칙이 하나("모든 지출은 쓴 주기에서 한 번만"). 카드 결제일이 언제든 동작 | 화면에 "청구 예정 금액"을 따로 보여줘야 함 | **채택** |

## 결과

**좋아지는 점**
- 이 프로젝트만의 이야기가 생긴다: "결제 순간에 다음 월급날까지 현금 흐름을 예측해서 개입한다."
- 이체에서 만드는 행 잠금·멱등키가 카드 결제·예산 검사에서 그대로 쓰여서, 돈 처리 로직이 한 곳에 모인다.
- 저축 목표, 자동이체 같은 팀 기획 기능이 예산 관리 안으로 합쳐져서 범위가 오히려 깔끔해진다.

**감수할 점**
- 거래내역·카드 사용내역에 **카테고리**가 필요하다. 팀 ERD에 없어서 테이블 변경이 생긴다.
- 분석 화면을 데모로 보여주려면 **6개월치 가상 거래 데이터**가 필요하다.
- 범위가 팀 기획과 달라서, 매일 아침 공유 때 차이를 설명해야 한다. 이 ADR과 `scope.md`의 "팀 기획과의 차이"로 설명한다.

**결정 대기** (추천안으로 기획, 구현 전 확인)
- 예산 초과 시 방식: 확인 모드 하나로 시작할지, 알림·잠금 모드도 만들지
- 목표 저축: 실제 적금 계좌로 자동이체할지, 예산에서 떼어두기만 할지
- 검사 대상: 계좌 이체까지 포함할지
- 6개월 데모 데이터 seed 준비 여부

**팀 뼈대와의 차이**
- 예산 관리 테이블 6개 추가 예정 (`budget.md`의 "필요한 데이터")
- 대출 관련 테이블을 만들지 않음
