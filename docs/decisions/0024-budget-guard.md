# 0024 — 예산 계산과 사람의 결제 확인

- 상태: 채택, 로컬 구현·검증 완료 (미커밋)
- 날짜: 2026-11-09

## 배경

[예산 기획](../planning/budget.md)의 자유 사용 가능액을 이체·카드 결제와 AI 상담에서 같은 기준으로 사용한다. 중단된 작업의 변경분을 현재 통합 브랜치에 복구했다.

## 결정

- 월급날부터 다음 월급날 전날까지를 주기로 삼는다. 수입에서 지출, 아직 안 낸 고정 지출, 남은 날의 필수 생활비, 목표 저축을 뺀다. 금액은 정수 원이다.
- `budget_profiles`, `fixed_expenses`, `budget_cycles`, `budget_decisions` 네 테이블을 추가한다. 목표는 현재 프로필에 한 개만 둔다.
- 목표 네 필드의 일부만 NULL인 행은 CHECK로 막는다. 이미 예산 테이블이 생성된 DB에도 적용되도록 후속 마이그레이션 `a61d9e72b4c8`에서 제약을 교체한다.
- 타인 이체와 체크·신용카드 결제를 검사한다. 내부 이체와 카드 대금은 중복 지출로 세지 않는다.
- 예산 초과 카드 결제는 `409 BUDGET_CONFIRMATION_REQUIRED`와 승인 번호를 반환한다. 이체는 기존 PIN 승인에 예산 영향과 필수 사유를 추가한다. 실행 시 다시 검사하며 확인 때보다 악화됐으면 실패한다. 긴급 선택은 사유와 함께 기록한다.
- 항상 통과 업종은 서버가 가맹점명으로 분류한 카드 결제에만 적용한다. 통과하더라도 지출과 결정 기록에 남긴다.
- 해지와 검사 완화는 기존 승인 대기 후 PIN으로 처리한다. `PATCH /budget` 강화는 200 요약을, 완화는 202 `BUDGET_UPDATE` 승인 요청을 반환한다. 수입 증가·필수 생활비 감소/삭제·고정 지출 감소/삭제/날짜 변경·목표 저축 감소/삭제·항상 통과 업종 추가가 완화다. 승인 화면의 서버 요약에 실제 변경값을 표시하며, 승인 전 설정이 달라졌으면 `BUDGET_CHANGED`로 실패하여 새 요청을 받는다. 고정 지출 이름은 중복을 금지한다.
- 카드 행 → 예산 주기 → 계좌 순서로 잠근다. 이체는 카드 행 없이 주기 → 계좌 순서다. SQLite 테스트는 PostgreSQL 행 잠금의 동시성 증거가 아니다.
- AI 도구는 `get_budget`, `check_budget` 조회 두 개뿐이다. AI는 서버 숫자를 인용하며 신청·변경·해지·초과 결제 승인을 수행하지 않는다. 이미 쓴 돈은 계좌 담당, 앞으로 쓸 돈은 예산 담당으로 라우팅한다.

## 검토한 대안

별도 예산 승인 API 대신 기존 승인 수명주기와 PIN 검증을 재사용한다. 목표별 테이블과 자동 분석은 현재 실행 검증에 필요하지 않아 추가하지 않았다.

## 결과와 남은 범위

계산·확인·실행 재검사를 공통 서버 코드로 처리한다. 신청·조회·수정·해지 화면과 홈 요약을 연결했다. 실제 Gemini 예산 답변, 라우팅 평가, PostgreSQL 동시 결제를 확인했다. 둘째 주기 분석, 이월, 목표 자동 이체는 후속 범위다. 상세 검증은 [복구 상태](../design-drafts/RESUME_STATUS.md)에 기록한다.

팀 뼈대에는 예산 도메인과 예산 담당 Agent가 없으며 이 구현이 추가한다.
