# 0025. 서버 공개 주소: DuckDNS + Caddy로 HTTPS

- 상태: 채택
- 날짜: 2026-11-11
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [배포 체크리스트](../deploy-checklist.md), [ADR 0020](0020-mobile-app-real-api.md) 모바일 웹 서빙

## 배경

- 포트폴리오용으로 AWS 서울 EC2(t3.small) 한 대에 앱과 PostgreSQL을 compose로 띄웠습니다. 보안 그룹의 인바운드(밖 → 서버) 규칙이 0개라 서버 안에서만 열리고 인터넷에서는 접속할 수 없었습니다.
- 토큰을 `sessionStorage`에 두므로 공개는 HTTPS 주소에서만 합니다(배포 체크리스트).
- 비용을 줄이려고 평일 낮에만 서버를 켜고 Elastic IP를 쓰지 않습니다. 켤 때마다 공인 IP가 바뀌어 IP로는 고정 링크를 줄 수 없습니다.

## 결정

1. `compose.prod.yaml`에 **Caddy**를 추가해 80·443만 밖에 엽니다. 앱의 8000번 포트는 서버 밖에 열지 않고, Caddy가 `app:8000`으로 넘깁니다. 인증서는 Caddy가 Let's Encrypt에서 자동으로 받고 갱신하며 `caddy_data` 볼륨에 둡니다.
2. 주소는 무료 **DuckDNS** 서브도메인(`<이름>.duckdns.org`)입니다. `duckdns` 컨테이너가 5분마다 지금 IP를 DuckDNS에 알립니다. 서버가 켜지면 컨테이너도 같이 올라와 바로 주소를 맞춥니다.
3. 서버 `.env`에 `DUCKDNS_SUBDOMAIN`, `DUCKDNS_TOKEN`을 둡니다. 레포에는 넣지 않고, 없으면 compose가 시작하지 않습니다. 컨테이너마다 필요한 값만 넘깁니다(Gemini 같은 다른 비밀은 넘기지 않음).
4. 보안 그룹 인바운드는 TCP 80·443만 엽니다. SSH(22)는 열지 않고 서버 관리는 계속 SSM Session Manager로 합니다.

## 검토한 대안

| 대안 | 장점 | 단점 | 고르지 않은 이유 |
|---|---|---|---|
| Elastic IP + 구입한 도메인 | IP 고정이라 단순함 | 도메인 비용, 서버가 꺼져 있어도 월 약 $3.6 | 비용 최소가 목표 |
| Cloudflare Tunnel | 인바운드를 열 필요 없음 | 내 도메인이 필요, 무료 임시 주소는 재시작마다 바뀜 | 도메인이 없음 |
| ALB + ACM 인증서 | AWS 표준 구성 | ALB만 월 $16 이상 | 서버 한 대에 과함 |
| uvicorn에서 직접 TLS | 컨테이너 하나 줄어듦 | 인증서 발급·갱신을 직접 구현 | Caddy가 자동으로 해 줌 |

## 결과

- 좋아지는 점: 무료 고정 주소와 HTTPS. 서버가 켜질 때 주소와 인증서가 사람 손 없이 맞춰집니다. 밖에 열린 포트는 Caddy의 80·443뿐입니다.
- 감수할 점: 서버를 켠 직후 수십 초는 이전 IP를 가리킬 수 있습니다. DuckDNS 서비스에 의존하고 주소에 `duckdns.org`가 붙습니다. 서버가 꺼진 시간(평일 18:00 이후·주말)에는 열리지 않습니다.
- 팀 뼈대와의 차이: 팀 뼈대에는 배포 구성이 없습니다. 이 레포만의 서버용 덮어쓰기 파일입니다.
