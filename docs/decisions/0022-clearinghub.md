# 0022. PIN 승인과 ClearingHub 타행 이체

- 상태 · 채택
- 날짜 · 2026-11-10

## 배경

팀원 은행에 송금하려면 외부 허브와 통신하면서 고객 PIN 승인과 장부의 일관성을 지켜야 합니다. 허브 응답이 유실되면 실제 입금 여부가 뒤늦게 확정될 수 있습니다.

## 결정

- 송금은 기존 JWT와 PIN을 사용합니다. 계좌 잠금 안에서 소유권, 상태, 잔액, 한도를 다시 확인하고 출금과 `APPROVED`를 커밋합니다.
- 승인 ID를 허브 거래 ID로 써서 재시작 뒤에도 같은 ID로 확인합니다. 승인 행의 처리 대기 상태가 출금 보류분을 나타냅니다. 서명이 맞는 확정 실패만 반환하고, 마감 전에 출금 계좌를 해지할 수 없습니다.
- 수신 API는 허브 서명 전용으로 분리합니다. 활성 입출금 계좌로 양의 원화 금액을 받으며, 영수증 기본키와 입금을 한 트랜잭션으로 저장합니다.

## 검토한 대안

PIN 승인 트랜잭션 안에서 허브를 호출하면 코드 흐름은 짧아지지만, 상대 은행 입금 후 로컬 트랜잭션이 롤백될 수 있습니다. 승인 행에 먼저 출금 결과를 남겨 이 간격에서 재시작해도 복구할 수 있게 합니다.

## 결과

팀 뼈대에 없던 수신 영수증과 결과 확인 작업을 추가합니다. 송금 상태는 허브가 확인할 때까지 대기할 수 있으며, 30분이 지나면 운영 로그에 거래 ID를 남기고 조회 간격을 늘립니다.

## 설정과 로컬 검증

송신은 `CLEARING_HUB_URL`, `CLEARING_PRIVATE_KEY`, `CLEARING_HUB_PUBLIC_KEY`, `CLEARING_BANK_CODE`, `CLEARING_API_KEY`를 사용합니다. 수신을 먼저 준비할 때는 개인키와 지문을 검증한 허브 공개키만 필요합니다. 운영 등록에는 공개 HTTPS의 `/interbank` 주소를 사용합니다. 허브와 테스트 키를 만든 뒤 [공식 빠른 시작](https://github.com/jjh7757/clearing-hub/blob/main/docs/SPEC.md)을 따라 로컬 초대로 등록할 수 있습니다.

```bash
uv run pytest -q tests/test_clearing.py
```
