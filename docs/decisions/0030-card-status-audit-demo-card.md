# 0030. 카드 정지·분실·해제를 감사 기록에 남기고, 데모 카드는 시작할 때마다 되살린다

- 상태: 채택
- 날짜: 2026-11-11
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0004](0004-approval-flow.md) 안전해지는 쪽은 바로, [ADR 0025](0025-https-caddy-duckdns.md) 서버 공개

## 배경

- 로컬에서 데모 카드가 어느새 **분실(LOST)** 상태였습니다. 화면 버튼, AI 상담, MCP 도구(`suspend_card lost=true`) 중 어디서 했는지, 언제였는지 알 길이 없었습니다. 카드 상태 변경은 `audit_logs`에 남지 않고, `cards`에는 수정 시각도 없습니다.
- 분실은 되돌릴 수 없습니다. 데모 비밀번호는 README에 공개돼 있어 공개 서버에서 **아무나 데모 카드를 분실 신고**할 수 있고, 그 뒤 방문자는 카드 화면에서 분실 카드만 봅니다. 서버 시작 seed는 데모 로그인 잠금만 풀고 카드는 그대로 둡니다.

## 결정

1. **카드 상태 변경을 감사 기록에 남긴다**(`audit_logs`, 같은 트랜잭션).
   - 정지·분실: `CARD_SUSPENDED`·`CARD_LOST`, `target`=카드 id, `detail`={`from`: 이전 상태, `requested_by`: WEB·AGENT·MCP}. `actor`는 입구에 따라 USER(화면)·AGENT·MCP.
   - 정지 해제(PIN 승인 실행): `CARD_UNSUSPENDED`, `actor`=USER(PIN을 넣은 사람), `detail`={`action_id`, `requested_by`(요청을 만든 입구)}.
   - `POST /cards/{id}/suspend`도 `X-Requested-By` 헤더를 받습니다(정보용, 보안 장치 아님).
2. **seed가 데모 카드를 보장한다**: 서버가 켜질 때 데모 사용자에게 **분실이 아닌 카드가 없으면** 체크카드(생활비 통장)를 새로 발급합니다. 분실 카드는 지우지 않고 기록으로 남깁니다. 정지 카드는 PIN으로 풀 수 있어 그대로 둡니다.
3. **카드 화면은 처음 열 때 쓸 수 있는 카드부터** 보여 줍니다(분실 카드는 목록에 남음).

## 검토한 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| seed가 분실 카드를 ACTIVE로 되돌림 | 카드 수가 늘지 않음 | "분실은 되돌릴 수 없다"는 규칙을 seed가 깨게 됨 |
| 데모 계정은 분실 신고 금지 | 원인 차단 | 시연에서 분실 신고 흐름을 보여 줄 수 없음, 계정별 예외 코드가 생김 |
| `cards.updated_at` 칼럼 추가 | 마지막 변경 시각은 알 수 있음 | 누가·어느 입구로 했는지는 모름. 마이그레이션도 필요. 감사 기록이 더 많은 걸 남김 |

## 결과

- 좋아지는 점: 카드가 왜 정지·분실됐는지 `audit_logs`로 답할 수 있습니다(입구까지). 공개 데모는 다음 시작 때 다시 시연 가능한 상태가 됩니다.
- 감수할 점: 누군가 분실 신고를 반복하면 데모 사용자 카드가 서버 시작마다 한 장씩 늘어납니다(평일 하루 한 번 시작이라 많지 않음). 카드 상태 변경 전에 쌓인 과거 변경은 기록이 없습니다.
- 팀 뼈대와의 차이: 팀 뼈대에는 카드·감사 기록 seed가 없습니다. 테이블 구조는 그대로입니다(마이그레이션 없음).
