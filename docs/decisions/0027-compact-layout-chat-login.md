# 0027. 화면 여백 줄이기, AI 상담 채팅형 개편, 로그인 화면 다시 디자인 (시안 B 선택)

- 상태: 채택
- 날짜: 2026-11-11
- 관련: [ADR 0021 공통 UI 부품](0021-ui-components.md), [구현 화면 버전 기록](../design-drafts/implemented/README.md), [공통 부품 사용법](../../frontend/ui.README.md)

## 배경

시안대로 구현한 화면(v1)을 실제로 써 보니 세 가지 문제가 있었다.

1. **세로로 너무 길다.** 은행명 머리글(64px) → 페이지 제목 → 도구 줄이 각각 한 줄씩 차지했다. 카드 화면은 "크게 보기 / 목록 보기"가 오른쪽에만 있으면서 한 줄을 다 썼고, 카드 그림이 나오기까지 약 330px이 지나갔다. 같은 높이에 놓을 수 있는 것(금액과 이체 버튼, 설명과 값)도 줄을 바꿔 놓았다.
2. **AI 상담이 대화처럼 보이지 않는다.** 선택한 시안 20번이 "질문 목록 버튼" 구조여서, 입력칸만 아래에 있고 나머지는 버튼 목록이었다. 무엇을 어떻게 입력하면 되는지 알려 주는 화면을 원했는데 "버튼을 고르는 화면"이 됐다. 입력줄과 배경도 같은 흰색이라 경계가 보이지 않았다.
3. **은행명이 모든 화면 왼쪽 위에 크게 반복된다.** 이미 앱 안에 들어와 있어 정보가 되지 않는다. 로그인 화면은 입력칸과 버튼이 붙어 있었고, 간편 로그인을 넣을 자리가 없었다.

## 결정

**한 줄에 놓을 수 있는 것은 한 줄에 둔다.**

- 탭 화면(상품·AI 상담·카드·전체)은 머리글 제목이 곧 페이지 제목(`h1`)이고, 오른쪽에 도구를 둔다. `header({ heading: true })`. 머리글 높이는 64px → 52px.
- 은행명은 홈 머리글에만 작게(15px) 둔다. 로그인 화면에서는 브랜드로 크게 쓴다.
- 카드 보기 전환은 아이콘만 있는 `iconToggle` 부품으로 만들어 제목 줄에 넣는다. 화면에는 아이콘만 보이지만 `aria-label`로 이름을 읽어 준다.
- 홈: 예산 가드는 "아이콘 + 설명 + 금액" 한 줄 카드, 계좌 행은 금액과 이체 버튼을 한 줄에 둔다 (340px 이하에서는 다시 세로).
- 고를 것이 없으면 그리지 않는다: 카드가 한 장이면 카드 선택 줄을 숨기고, 중복된 "전체보기"·검색 줄·제목을 뺀다. 자주 쓰지 않는 PIN 변경 폼은 접어 둔다.

**AI 상담은 처음부터 대화 모양이다.**

- 빈 화면에 AI 인사 말풍선을 먼저 보여 주고, 예시 질문을 "아직 보내지 않은 내 말풍선"(점선 테두리, 오른쪽 정렬)으로 보여 준다.
- 예시를 누르면 **보내지 않고 입력칸에 채운다.** 이체 금액처럼 고쳐서 보낼 수 있어야 하고, 한 번 눌러 바로 AI 호출(하루 한도, [ADR 0026](0026-ai-daily-limit.md))이 나가는 것도 막는다.
- 대화 영역은 옅은 회색(`--ui-surface`), 입력줄은 흰색 + 윗선 + 옅은 그림자로 구분한다. 답변을 기다리는 동안은 점 세 개가 움직이는 말풍선을 보여 준다(동작 줄이기 설정이면 멈춤).
- 서버 연결(`/chat/stream`, 승인 대기 → PIN 창)은 바꾸지 않았다.

**로그인 화면은 세 시안을 구현해 비교하고 B(네이비 배경 + 흰 시트)를 골랐다.**

- 처음 고친 A(캐릭터 + 알약 모양 입력칸)에 더해, 캐릭터 없이도 성립하는 B(네이비 배경 위 큰 인사말, 아래에서 올라온 흰 시트에 폼)와 C(왼쪽 정렬 큰 글자 + 카드의 사선 띠, 밑줄 입력칸)를 만들었다. [비교 캡처](../design-drafts/implemented/README.md).
- **B를 기본으로 쓴다.** 입력칸은 회색 면에 이름표가 칸 위에 보이고, 로그인 버튼과는 14px 띄운다. 회원가입과 데모 계정은 한 줄 글자 링크로 낮춘다.
  - *2026-11-11 리뷰 반영 ([v3 캡처](../design-drafts/implemented/README.md)):* 입력칸·로그인 버튼은 양옆 여백을 늘리고 완전히 둥글게(알약) 했다. "아이디·비밀번호"는 칸 위 이름표 대신 칸 안의 흐린 안내 글(placeholder)로 넣고 입력 글자는 가운데 정렬한다(화면 낭독용 label은 숨겨 둔다). 간편 로그인은 흐린 구분선 가운데에 "간편 로그인"을 두고, 그 아래 가운데에 둥근 정사각형 버튼 두 개를 놓는다. 버튼 안에 로고(위)와 Google·NAVER(아래)를 함께 넣어 글자까지 누르는 영역이 된다(84×76px). 중간에 만든 가로 버튼 두 줄 안(로고 + "구글 간편로그인")은 [보관](../design-drafts/implemented/README.md)했다. 이 버튼은 다른 화면에서도 쓰도록 공통 부품 `ui.mjs`의 `socialButton`으로 만들었다.
- **고르지 않은 A·C는 기록으로만 남긴다.** 앱에는 로그인 화면을 B 하나만 두고, A·C의 코드와 캡처는 [보관 폴더](../design-drafts/implemented/login-options-2026-11-11/archived-code/)에 둔다. 세 시안은 폼 이름과 버튼 액션이 같아서, 캐릭터가 확정되면 A로, 카드 디자인과 맞추려면 C로 HTML·CSS만 바꿔 돌아갈 수 있다.
  - *2026-11-11 수정:* 처음에는 A·C를 앱에 남겨 `?login=a`, `?login=c` 주소로 열리게 했다. 하지만 고객이 쓰는 앱에 안 쓰는 로그인 화면이 숨어 있으면 관리할 것만 늘고 누구나 주소로 열 수 있어서, 그 주소들을 없애고 보관 폴더로 옮겼다.
- **간편 로그인(Google·네이버)은 자리만 만든다.** B에서는 로고와 이름이 함께 든 둥근 정사각형 버튼 두 개다(`socialButton`, Google 왼쪽). 아직 연결하지 않았고, 누르면 "준비 중" 안내만 한다. 실제 연결은 별도 결정(인증 구조 [ADR 0005](0005-auth.md)의 후속)으로 다룬다.

**색은 역할을 정리한다.** 주 파랑을 조금 선명하게(`#235b91` → `#1d5fa8`), 구분선을 조금 진하게(`#edf0f3` → `#e6eaef`) 했다. 회색 면은 `--ui-surface` 하나로 모으고, 크림색은 강조 카드에만 쓴다.

## 검토한 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 은행명 머리글을 모든 화면에 두되 크기만 줄이기 | 브랜드가 계속 보인다 | 제목 줄과 합칠 수 없어 한 줄이 그대로 남는다. 하단 탭이 이미 "앱 안"임을 알려 준다 |
| 보기 전환을 "크게 보기 / 목록 보기" 글자 그대로 왼쪽으로 옮기기 | 글자라 뜻이 분명하다 | 제목 줄에 넣기엔 길다. 둘 중 하나 고르기는 아이콘 전환이 흔한 표현이다 |
| AI 상담 예시를 누르면 바로 보내기 | 한 번에 답이 온다 | 이체 예시가 그대로 나가고, 고쳐 쓸 수 없고, AI 호출 한도를 쓴다. "이렇게 입력한다"를 보여 주려는 목적과도 다르다 |
| 시안 20번(질문 목록) 유지하고 입력줄에 선만 추가 | 변경이 작다 | 대화 서비스로 보이지 않는 문제가 남는다 |
| 간편 로그인 버튼을 가로 두 칸으로 | 세로 길이가 짧다 | 처음엔 이렇게 했으나, 주 버튼과 같은 크기의 버튼 두 개가 나란히 있어 로그인 버튼과 경쟁했다. 세로로 두고 작게 낮췄다 |
| 간편 로그인 자리를 비활성(회색) 버튼으로 | 안 된다는 것이 바로 보인다 | 회색 로고는 완성되지 않은 화면처럼 보인다. 눌렀을 때 이유를 알려 주는 편이 낫다 |

## 결과

- 좋아지는 점
  - 카드 화면은 카드 그림이 약 60px 지점에서 시작한다(전 약 330px). 홈·상품·전체 메뉴도 첫 화면에 들어오는 내용이 늘었다.
  - AI 상담을 처음 여는 사람이 무엇을 어떻게 입력하면 되는지 대화 모양 그대로 본다.
  - 로그인 화면에 간편 로그인을 붙일 자리가 생겼다.
  - 전/후 화면을 [버전별 캡처](../design-drafts/implemented/README.md)로 남겨, 다음 개편 때 같은 조건으로 비교할 수 있다.
- 감수할 점
  - AI 상담·전체 메뉴는 선택한 시안(20번·25번)과 달라졌다. 시안 문서에 이력으로 남겼다.
  - 예시 질문이 9개에서 5개로 줄었다(분야마다 하나).
  - 간편 로그인 버튼은 보이지만 동작하지 않는다. 연결 전까지 "준비 중" 안내가 뜬다.
  - 로그인 시안 A·C를 다시 쓰려면 보관 폴더의 코드를 앱에 다시 붙여야 한다. 대신 앱에는 쓰는 화면만 남는다.
  - B는 화면 위쪽이 어두워 밝은 다른 화면과 대비가 크다.
  - 계좌 상세·이체·예산 화면은 이번 범위에 넣지 않았다.
- 팀 뼈대와의 차이: 모바일 웹의 화면 배치와 공통 부품(`iconToggle`, `header`의 `heading`)만 바꿨다. 서버 구조·DB·API 규약은 그대로다.
