# 0013. Agent·RAG 구현 계획: Gemini 무료 티어, 우리 문서 + 상품 DB, RAG → MCP → Agent

- 상태: 채택
- 날짜: 2026-11-06
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0004](0004-agent-integration.md) Agent 연결, [ADR 0006](0006-agent-orchestration.md) 감독관 구조, [scope.md](../planning/scope.md)

## 결정

1. **LLM과 임베딩은 Gemini 무료 티어**를 쓴다. 기본값은 답변 `gemini-3.8-flash`, 임베딩 `gemini-embedding-2`(사용자 결정, 768차원으로 줄여 저장)이고 `.env`(`GEMINI_MODEL`, `GEMINI_EMBEDDING_MODEL`)에서 바꿀 수 있다. 지난 프로젝트의 `gemini-2.5-flash`는 지원 종료 예정(2026-12-01부터 `gemini-3.5-flash-lite`로 넘어감)이라 쓰지 않는다. 키(`GEMINI_API_KEY`)는 사용자가 직접 발급해 `.env`에만 둔다. **테스트와 CI는 Gemini를 부르지 않는다**(가짜 임베딩·가짜 LLM). GitHub Secrets에 키를 넣지 않는다.
2. **RAG 문서는 두 가지**다(사용자 결정).
   - 계좌·카드 **상품 DB**: 상품 설명, 가입 조건, 우대금리, 카드 혜택. 상품 하나 = 청크 하나. DB가 바뀌면 다시 색인한다.
   - 이 앱의 실제 규칙을 **조항 형식으로 쓴 데모 약관·이용 안내**(이체 한도·PIN 승인, 카드 결제·대금·연체, 계좌 해지 등). 내용은 코드와 ADR에서 가져와서, 답이 실제 동작과 맞는다.
   - 지난 RAG 레포의 문서(대부분 증권 약관)는 옮기지 않는다. 대신 **방법**을 옮긴다: 조항 1개 = 청크 1개(1,200자가 넘으면 ①② 항 경계에서 나눔), 벡터 + 단어(Kiwi BM25) 하이브리드를 RRF(60)로 합침, k = 5, 근거 인용, 답할 수 없으면 지어내지 않음, 정답 세트로 Hit@k·MRR 측정.
3. **PR은 RAG → MCP → Agent 순서**로 나눈다(사용자 결정). 대출·예산 Agent와 예산 컨텍스트·코멘트 노드(ADR 0006)는 그 기능을 만들 때 붙인다.
4. **실행 추적(Langfuse)은 Agent PR 다음에 따로** 붙인다(사용자 결정).

## PR별 범위

### ① RAG
- 저장: PostgreSQL **pgvector**(이미지 `pgvector/pgvector:pg17`), 테이블 `rag_chunks`(청크 id, 출처, 제목 경로, 본문, 본문 해시, 임베딩 768). 문서가 수백 개 이하라 근사 인덱스 없이 정확 검색.
- 색인: 시스템 API(서버 키)로 다시 만든다. **본문 해시가 바뀐 청크만 다시 임베딩**해서 무료 한도를 아낀다.
- 검색·답변 API: 검색 결과(근거)와 함께 답한다. 답변은 JSON으로 받고, 인용은 **검색된 청크 id 안에서만** 허용한다. 근거가 없으면 "자료 없음"으로 답한다.
- 평가: 질문 30개 안팎의 정답 세트(정답 청크 id)로 Hit@1·Hit@5·MRR. 실행은 사람이 명령으로(무료 한도 안).

### ② MCP 서버
- ADR 0006 표의 계좌·카드·상품 도구. 도구는 **사용자 토큰으로 REST API를 부른다**(Agent는 사용자보다 큰 권한이 없음).
- 넣지 않는 것: 승인·PIN API, 카드 결제(가맹점 시뮬레이터, ADR 0010), `/system/*`.

### ③ Agent
- LangGraph 감독관 + 계좌·카드·상품 Agent 3개, 도구는 MCP(`langchain-mcp-adapters`), 대화 상태는 PostgreSQL 체크포인터, 채팅 API.
- 감독관 출력은 구조화해서 정해진 Agent 이름만 고른다. 라우팅 정확도를 재는 작은 평가 세트를 둔다.

### ④ 실행 추적
- Langfuse(무료 클라우드 또는 Docker는 그때 정함). ADR 0006의 "다시 검토할 조건"(p95 8초 등)을 여기서 잰다.

## 배경

- 과제 필수: 자연어 입력(맥락 유지, 되묻기), 지난 미니 프로젝트의 RAG.
- 지난 RAG 레포(financial-rag-agent-solo)는 금융 PDF 23개를 다뤘지만 대부분 증권 약관이어서, "내 이체 한도", "카드 연체되면?" 같은 이 앱의 질문에는 답하지 못한다.
- 대출·예산 기능은 아직 없다.

## 결과

**좋아지는 점**
- 비용 0원으로 시작한다(무료 티어, 결제 수단을 등록하지 않으면 과금 없음).
- RAG 답이 코드의 실제 규칙과 같아서, 틀리면 문서와 코드 중 어디가 틀렸는지 바로 안다.
- PR마다 혼자 동작을 보여 줄 수 있다(검색 API → MCP 도구 → 채팅).

**감수할 점**
- 무료 티어는 입력이 구글 모델 개선에 쓰일 수 있다. **데모 데이터만** 넣는다.
- 무료 티어의 분당·하루 호출 한도가 있어서 평가를 한 번에 많이 돌릴 수 없다.
- 데모 약관은 우리가 쓴 문서라 실제 공문서가 아니다. 문서 머리에 그렇게 적는다.
- 인터넷·키가 없으면 RAG와 Agent가 동작하지 않는다. 그때 API는 분명한 오류(`503`)를 낸다.

**팀 뼈대와의 차이**
- 팀 뼈대에는 Agent·RAG가 없다. 이 레포는 pgvector RAG + MCP + LangGraph 감독관으로 만든다.
