# 0008. 계좌 개설 정책: 남의 계좌는 404, 기본 이체 한도, 일련번호, 예금은 이체와 함께

- 상태: 채택 (결정 4의 예금 개설은 승인 흐름으로 구현됨: `POST /accounts/deposits`)
- 날짜: 2026-11-05
- 관련 PR: #9

## 결정

1. **남의 계좌에 접근하면 403이 아니라 `404 ACCOUNT_NOT_FOUND`**로 답한다. 없는 계좌와 같은 응답이다.
2. 입출금 계좌의 **이체 한도 기본값은 1회 100만 원, 1일 500만 원**이다. 한도를 **올리는** 것은 보안을 약하게 해서 승인(PIN) 기능과 함께 만든다.
3. 계좌번호 **일련번호는 같은 `110-TPP-` 안에서 가장 큰 번호 + 1**이다. 같은 상품을 동시에 열어 번호가 겹치면 `409 ACCOUNT_NUM_CONFLICT`로 다시 시도하게 한다. 999999를 넘으면 `409 ACCOUNT_NUM_EXHAUSTED`.
4. **예금은 이 PR에서 열지 않는다.** 맡길 돈을 입출금 계좌에서 옮겨야 해서, 이체·승인(ADR 0004, 0007)이 생긴 뒤 같은 흐름으로 연다(`400 DEPOSIT_NEEDS_TRANSFER`).
5. 적금의 우대금리는 **개설 때 알 수 있는 것만** 적용한다(마케팅 동의, 첫 예·적금). 급여이체 우대는 나중에 조건을 확인하는 기능이 생기면 적용한다. 우대 상한에 걸리면 `rate_detail`에 깎인 만큼(`PREFERENTIAL_CAP`)을 남겨서 스냅샷만으로 적용 금리를 다시 계산할 수 있게 한다.

## 배경

- ERD의 "팀에서 정해야 할 것"에 이체 한도 기본값과 일련번호 발급 방식이 남아 있었다. 계좌 개설을 만들려면 정해야 했다.
- 팀 기획의 API 실패 예시는 남의 계좌에 `403 ACCOUNT_FORBIDDEN`이었다.

## 검토한 대안

### 남의 계좌 응답

| 대안 | 결과 |
|---|---|
| 403 (팀 기획) | "그 계좌가 있지만 당신 것이 아니다"를 알려 줌. 계좌번호·id를 바꿔 가며 다른 사람 계좌가 있는지 찾아볼 수 있음. 버림 |
| **404** | **채택**. 없는 계좌와 구분되지 않음. GitHub 등이 남의 비공개 저장소에 쓰는 방식 |

### 일련번호

| 대안 | 결과 |
|---|---|
| DB 시퀀스 (팀 메모의 추천) | 동시에 열어도 겹치지 않음. 테스트용 SQLite에 시퀀스가 없어서 두 가지 코드가 필요. 지금은 버림 |
| 계좌 id를 일련번호로 | 상품별로 번호가 1부터 시작하지 않고, id는 INSERT 뒤에 정해져서 번호를 나중에 바꿔야 함. 버림 |
| **같은 접두어 안의 최댓값 + 1, 겹치면 409** | **채택**. 단순하고 상품별로 1부터. 동시 개설은 드물어서 감수. 자주 겹치면 시퀀스로 바꾼다(코드에 shortcut 주석) |

## 결과

**좋아지는 점**
- 계좌 존재 여부를 응답으로 알아낼 수 없다.
- 한도·번호 규칙이 문서와 코드(`domains/accounts/service.py`의 상수)에 한 번씩만 있다. seed도 같은 상수를 쓴다.

**감수할 점**
- 같은 상품을 동시에 열면 한쪽이 409를 받는다.
- 예금은 다음 PR까지 API로 열 수 없다(데모 사용자는 seed로 예금이 있음).

**팀 뼈대와의 차이**
- 남의 계좌·카드: 403 → 404
- 이체 한도 기본값, 일련번호 방식: 팀 뼈대에서는 미정 → 위 값으로 정함
