# 0011. 신용카드 대금 출금: 시스템 API, 결제일 전날까지 전부, 못 내면 연체

- 상태: 채택
- 날짜: 2026-11-06
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0007](0007-money-execution-and-budget-guard.md) 실행 함수, [ADR 0010](0010-card-payments.md) 카드 결제

## 결정

1. **대금 출금은 시스템 작업 API `POST /system/card-bills/run?run_date=`로 실행한다.** 사용자 토큰이 아니라 **서버 키**(`X-System-Key`, `.env`의 `SYSTEM_API_KEY`)로만 부른다. 키를 설정하지 않으면 API가 꺼진다. 매일 자동으로 부르는 것(cron 등)은 이 API를 바깥에서 부르면 된다.
2. **결제일(`payment_day`)이면 결제일 0시(한국) 전에 쓴 `UNBILLED` 사용분을 전부 `BILLED`로 묶는다.** 실제 카드사의 "이용 기간"(예: 전월 1일~말일)은 쓰지 않는다.
3. 묶인 `BILLED` 합계를 결제 계좌에서 **전액 출금**하고(`CARD_BILL`, 카테고리 "카드 대금"), 사용분을 `PAID`로 바꾸며 출금 줄을 `bill_tx_id`에 남긴다. 출금은 실행 함수(`money.execute_card_ledger`)를 지난다.
4. **잔액이 모자라면 출금하지 않고 `BILLED`(연체)로 남긴다.** 다음 실행 때 결제일이 아니어도 다시 시도한다. 연체가 있는 동안 그 카드는 `409 CARD_OVERDUE`로 결제할 수 없다. 연체 이자는 없다.
5. **같은 날짜로 다시 불러도 한 번만 출금한다.** 이미 `PAID`인 것은 다시 묶이지 않는다.
6. **오늘(한국) 이후 날짜로는 실행할 수 없다**(`400 RUN_DATE_IN_FUTURE`). 아직 오지 않은 결제일을 앞당겨 청구하지 않기 위해서다.
7. **카드마다 트랜잭션 하나**다. 카드 행을 잠그고(결제와 같은 잠금, 순서 카드 → 계좌) 처리해서, 대금을 묶는 동안 같은 카드의 결제·취소가 끼어들지 않는다. 한 카드가 실패해도(잔액 부족은 연체, 예상 못 한 오류는 그 카드만 되돌리고 `failed_cards`) 다른 카드는 진행된다.
8. **청구 뒤 취소**: 아직 안 낸 것(`BILLED`)은 기록만 취소(대금에서 빠짐), 이미 낸 것(`PAID`)은 결제 계좌로 환불(`REFUND`)한다.

## 배경

- ADR 0010에서 신용카드는 사용 기록만 남기고 돈은 대금 출금일에 나가도록 미뤘다. 대금 출금이 없으면 신용 한도가 돌아오지 않는다.
- 레포에 스케줄러가 없다. 이자·적금 자동 납입도 나중에 같은 방식이 필요하다.

## 검토한 대안

### 실행 방식

| 대안 | 결과 |
|---|---|
| 앱 안 스케줄러 (APScheduler 등) | 의존성이 늘고, 서버가 여러 대면 중복 실행을 따로 막아야 하며, 날짜를 바꿔 테스트하기 어려움. 버림 |
| 사용자 선결제만 | 결제일 자동 출금이 없어 실제 카드와 다름. 버림 |
| **서버 키로 부르는 시스템 API + 날짜** | **채택**. 같은 날짜로 다시 불러도 안전하고, 날짜를 넣어 시연·테스트할 수 있음 |

### 잔액 부족

| 대안 | 결과 |
|---|---|
| 있는 만큼 부분 출금 | 사용분마다 갚은 금액을 적을 칸과 청구서 테이블이 필요. 버림 |
| **출금 안 함, 연체로 남기고 결제 막기** | **채택**. 사용분 상태 하나로 표현됨 |

## 결과

**좋아지는 점**
- 대금을 내면 신용 한도가 돌아온다.
- 시스템 작업의 입구가 하나 생겨서, 이자·자동 납입도 같은 방식(서버 키 + 날짜 + 다시 불러도 안전)으로 붙일 수 있다.
- 사용분마다 어느 대금 출금으로 갚았는지(`bill_tx_id`) 추적할 수 있다.

**감수할 점**
- 실행을 하루 빼먹으면 그 결제일의 청구는 다음 달 결제일로 밀린다(연체 재시도는 매일 됨). 매일 부르는 것은 바깥(cron)의 책임이다.
- 청구서(월별 명세서) 테이블은 없다. 명세서는 `bill_tx_id`로 묶어 보여 준다.
- 연체 이자, 부분 납부, 연체 알림은 없다.
- 서버 키 하나로 보호한다. 키가 새면 누구나 대금 출금을 부를 수 있다. 돈이 남에게 가지는 않지만, 지난 날짜로 부르면 그 날이 결제일인 카드의 청구가 일찍 일어나고 잔액이 모자라면 연체가 생겨 결제가 막힐 수 있다. 미래 날짜는 막는다. 시도 횟수 제한은 없다.
- 결제 계좌를 쓸 수 없어(`ACCOUNT_NOT_FOUND`) 못 낸 것도 연체로 센다. 로그에 이유 코드를 남긴다. 계좌 해지 기능을 만들 때 같이 다룬다.

**팀 뼈대와의 차이**
- 팀 뼈대: 대금 출금 없음 → 이 레포: 시스템 API, `billing_status` 흐름 `UNBILLED → BILLED → PAID`, `bill_tx_id`
