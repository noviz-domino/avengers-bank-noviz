# 0010. 카드 결제: 가맹점 시뮬레이터, 카드 행 잠금, 신용 한도는 안 갚은 금액

- 상태: 채택
- 날짜: 2026-11-05
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0004](0004-agent-integration.md) 승인, [ADR 0007](0007-money-execution-and-budget-guard.md) 실행 함수, [ADR 0009](0009-card-policy.md) 카드

## 결정

1. **`POST /cards/{id}/payments`는 가맹점 결제를 흉내 내는 API**다. 로그인한 카드 주인이 부르고 **PIN 없이 바로** 결제된다. 실제 카드 결제에 은행 PIN이 없는 것과 같다. **Agent·MCP 도구에는 넣지 않는다.**
2. **같은 카드의 결제·취소는 카드 행을 잠그고(`SELECT … FOR UPDATE`) 한 줄로 처리**한다. 잠근 뒤 요청 번호 → 카드 상태 → 1일 한도 → (신용) 신용 한도 / (체크) 잔액 순서로 검사한다. 잠금 순서는 **카드 → 계좌**다.
3. **체크카드**는 결제 계좌에서 바로 출금한다. 잔액·장부는 실행 함수(`money.execute_card_ledger`)만 바꾼다(ERD 규칙 13). 장부에는 `CARD_PAYMENT`, 취소하면 `REFUND`가 쓴 업종 그대로 쓰인다.
4. **신용카드**는 사용 기록만 남기고(`billing_status = UNBILLED`) 돈은 대금 출금일에 나간다(대금 출금 PR).
5. **신용 한도는 "안 갚은 사용액" 합계**(`billing_status != PAID`)로 센다. 그래서 `cards.monthly_limit`을 **`credit_limit`으로 이름을 바꿨다**. 기본 300만.
6. **1일 한도는 오늘(한국 날짜) 취소하지 않은 사용액 합계**다. 누적액은 저장하지 않고 계산한다(ERD 규칙 11). 취소하면 한도가 돌아온다.
7. **요청 번호(`idempotency_key`)는 카드마다 unique**다. 같은 번호로 다시 오면 처음 결과를 `200`으로 돌려주고, 내용이 다르면 `409 IDEMPOTENCY_KEY_REUSED`.
8. 취소는 **전액만**. 정지·분실 카드도 취소(환불)는 된다. 청구된 뒤의 취소는 대금 출금 PR에서 만든다.

## 배경

- 실제 결제는 가맹점이 카드사로 보내지만, 이 앱에는 가맹점이 없다. 사용내역·한도·예산 분석을 보여 주려면 결제를 만드는 입구가 필요하다.
- 결제는 PIN 승인이 없어서, 동시에 두 번 오면 한도·잔액 검사가 둘 다 통과할 수 있다. 이체는 계좌 행을 잠가서 막는데, 신용카드는 계좌를 건드리지 않는다.
- 실제 신용카드 한도는 한 달 사용액이 아니라 갚지 않은 금액이다. 이번 달에 다 써도 대금을 내면 다시 쓸 수 있다.

## 검토한 대안

### 결제 입구

| 대안 | 결과 |
|---|---|
| 결제도 PIN 승인 대기 | 안전하지만 실제 카드 결제 흐름과 다르고, 예산 가드("예산 안이면 바로")와도 맞지 않음. 버림 |
| **가맹점 시뮬레이터, PIN 없음, Agent 도구 제외** | **채택**. 토큰만 가진 Agent가 결제를 만들 수 없음 |

### 동시 결제

| 대안 | 결과 |
|---|---|
| 계좌 행만 잠금 | 신용카드는 계좌를 안 건드려서 한도 검사가 뚫림. 버림 |
| 조건부 UPDATE로 누적액 칸 갱신 | 누적액을 저장해야 함(ERD 규칙 11 위반, 취소·청구 때 동기화 버그). 버림 |
| **카드 행 잠금 후 합계 계산** | **채택**. 체크·신용 같은 방식, 카드 하나의 결제만 줄을 섬 |

### 신용 한도

| 대안 | 결과 |
|---|---|
| 달력 기준 한 달 사용액 | 단순하지만 실제 카드와 다르고, 대금을 내도 한도가 안 돌아옴. 버림 |
| **안 갚은 사용액** | **채택**. 대금 출금 PR에서 `PAID`로 바뀌면 한도가 돌아옴 |

## 결과

**좋아지는 점**
- 체크카드 결제도 이체와 같은 실행 함수를 지나서, 예산 가드를 한 곳에 넣을 수 있다.
- 같은 결제가 두 번 와도, 동시에 와도 한 번만 결제된다.
- 컬럼 이름이 실제 의미(신용 한도)와 같다.

**감수할 점**
- 대금 출금이 아직 없어서, 신용카드는 쓴 만큼 한도가 계속 줄어든다(대금 출금 PR에서 해결).
- 부분 취소, 해외 결제, 할부는 없다.
- 결제 API를 Agent 도구에서 빼는 것은 도구 목록(ADR 0006)에서 지키는 규칙이다. 서버가 "사람이 불렀는지"를 따로 확인하지는 않는다.
- SQLite 테스트는 `FOR UPDATE`를 무시해서, 동시성은 PostgreSQL에서만 보장되고 테스트로 증명하지 않았다.

**팀 뼈대와의 차이**
- 팀 뼈대: `card_payments` 등 카드 종류별 테이블, 누적액 저장 → 이 레포: `card_transactions` 하나, 누적액은 계산, 체크카드는 계좌 장부와 연결(`account_tx_id`)
