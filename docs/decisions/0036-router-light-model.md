# 0036. 라우터만 가벼운 모델로: gemini-3.5-flash-lite, 생각 수준 minimal

- 상태: 채택 (→ [0037(이름 선택지)](0037-router-named-targets.md): 이 모델은 temperature를 무시해서 같은 질문도 가끔 다르게 표시한다. 틀린 답이 되는 길은 코드 장치로 막음)
- 날짜: 2026-11-27
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0016(응답 시간 측정)](0016-agent-latency-tracing.md) 생각 수준, [ADR 0034(빠른 길)](0034-agent-quick-lanes.md)·[ADR 0035(검색형 빠른 길)](0035-agent-search-quick-lane.md) 빠른 길, [조사 보고서](../research/agent-latency-and-rag.md) 2순위 제안, [평가 기록](../evaluations/agent-latency/README.md)

## 배경

- 라우터는 모든 턴에 한 번씩 돈다. 빠른 길(ADR 0034(빠른 길)·0035(검색형 빠른 길))로 흔한 질문이 LLM 한 번이 되자 그 한 번이 곧 라우터라서 라우터 속도가 답 시간 대부분이 됐다.
- 담당과 라우터가 같은 `gemini-3.8-flash`(생각 `low`)를 썼다. 이 모델은 생각 수준 `minimal`을 지원하지 않는다(ADR 0016(응답 시간 측정)).
- 라우터가 하는 일은 담당 고르기와 빠른 길 표시, 검색 기간·업종 채우기다. 긴 글을 쓰거나 도구 결과를 해석하지 않는다.

## 결정

1. **라우터 전용 모델 설정을 둔다** (`GEMINI_ROUTER_MODEL`, `GEMINI_ROUTER_THINKING`). 기본값은 `gemini-3.5-flash-lite`와 생각 `minimal`. 담당 Agent와 RAG는 그대로 `gemini-3.8-flash`(생각 `low`).
2. **실제 Gemini로 돌 때만 쓴다** (`agent/llm.py`의 `router_for`). 테스트의 가짜 모델로 돌 때는 라우터도 같은 가짜 모델이라 테스트가 외부 호출을 하지 않는다.
3. **되돌리기 쉽게**: 담당과 같은 모델로 돌리려면 환경 변수 `GEMINI_ROUTER_MODEL=gemini-3.8-flash`, `GEMINI_ROUTER_THINKING=low`.

## 측정 (2026-11-27, 같은 질문 21개, 같은 시간대에 연달아, 한 번씩)

| 라우터 | 담당 맞힘 | 질문당 LLM 호출 | p50 | p95 | 원본 |
|---|---|---|---|---|---|
| gemini-3.8-flash, low (기준선) | 21/21 | 2.2 | 8.0초 | 13.7초 | [05](../evaluations/agent-latency/2026-11-27_05-before-router.json) |
| **gemini-3.5-flash-lite, minimal** | **21/21** | **2.2** | **4.2초** | **11.5초** | [06](../evaluations/agent-latency/2026-11-27_06-router-flash-lite.json) |
| gemini-3.6-flash, minimal | 21/21 | 2.0 | 4.5초 | 11.4초 | [07](../evaluations/agent-latency/2026-11-27_07-router-3.6-flash.json) |

**칸 채우기 시험** (평가 세트는 담당만 채점해서 따로 확인): 까다로운 질문 9개("지난달 편의점", "어제 카페", "이번 주 술값", "11월 1일부터 10일까지 들어온 돈", "생활비 통장 잔액만", "30만 원 써도 돼?" 등)에서 세 모델이 담당·빠른 길 표시·검색 기간·업종·방향을 **모두 똑같이** 채웠다. "지난달"은 10월 1~31일, "이번 주"는 월요일(11월 23일)부터, "식비"는 식사와 외식·술자리, 특정 계좌만이나 금액이 붙은 질문은 빠른 길로 표시하지 않았다. 라우터 한 번은 약 2.5초 → 1.0초. 원본: [08](../evaluations/agent-latency/2026-11-27_08-router-slot-probe.txt), 시험 스크립트: [`router_slot_probe.py`](../evaluations/agent-latency/router_slot_probe.py)

- flash-lite와 3.6-flash는 전체 시간이 비슷하고 칸 채우기 결과가 같았다. 라우터 한 번이 더 짧은(1.0초 대 1.8초) flash-lite를 골랐다.
- 빠른 길 질문은 대부분 1초 안팎이 됐다(잔액 1.5초, 이번 달 식비 1.1초, 남은 예산 0.9초). 담당 Agent를 거치는 질문은 담당 호출이 그대로라 2~3초쯤 준다.
- 기본값을 바꾼 뒤 실제 앱에서도 확인했다: "이번 달 식비" 1.2초(서버 합계 12,000원과 같음), "체크카드 한도" 9.1초(카드 담당이 처리, 남은 한도 1,000,000원).

## 검토한 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 담당 Agent도 가벼운 모델로 | 더 빨라짐 | 담당은 도구 결과를 읽고 설명하는 일이라 품질 위험이 큼. 답 품질 채점 세트가 없어서 재지 못함 |
| gemini-3.6-flash, minimal | 질문당 호출이 조금 적게 나옴 | 전체 시간은 비슷하고 라우터 한 번이 flash-lite보다 느림 |
| 라우터 없이 규칙(키워드)으로 담당 고르기 | LLM 0번 | "카드 대금 못 내면"(상품)과 "내 카드 대금 밀렸어?"(카드) 같은 구분을 규칙으로 유지하기 어려움 |

## 결과

- 좋아지는 점: p50 8.0초 → 4.2초. 빠른 길을 타는 흔한 질문은 1초 안팎이다. 담당 맞힘은 그대로 21/21이다.
- 감수할 점: 모델이 둘이 되어 무료 티어 한도도 모델별로 따로 쓴다(라우터 호출은 flash-lite 한도). 질문 세트가 21개라 드문 표현에서 가벼운 모델이 다르게 고를 수 있다. 질문이 늘면 같은 방법으로 다시 잰다.
- 측정은 한 번씩이라 p95는 가장 느린 1~2개 질문("카드 한도랑 내 잔액" 같은 복합 요청)의 값이다. 남은 느린 질문은 담당 Agent를 거치는 한도·상세·카드 사용내역이다.
