# 설계 결정 기록 (ADR)

설계나 DB 구조를 바꿀 때 **왜 그렇게 정했는지**를 남기는 문서입니다. 코드만 보면 "무엇"은 알 수 있지만 "왜"는 알 수 없어서, 나중에 다시 바꾸려는 사람(미래의 나, 팀원)이 같은 고민을 반복하지 않게 합니다.

## 목록

|---|---|---|---|
| [0001](0001-account-number-format.md) | 계좌번호 형식과 상품 코드 | 채택 | 2026-11-04 |

## 새로 쓰는 법

1. 다음 번호로 파일을 만듭니다: `NNNN-짧은-제목.md`
2. 아래 틀을 채웁니다
3. 위 목록에 한 줄 추가합니다
4. 코드 변경과 **같은 PR**에 넣고, PR 본문에 링크합니다

이미 채택한 결정을 바꿀 때는 기존 문서를 고치지 않고 새 ADR을 씁니다. 기존 문서의 상태만 "대체됨 (→ NNNN)"으로 바꿉니다.

```markdown
# NNNN. 제목

- 상태: 제안 / 채택 / 대체됨 (→ NNNN)
- 날짜: YYYY-MM-DD
- 관련 PR:

## 배경
무엇이 문제였나

## 결정
무엇으로 정했나

## 검토한 대안
| 대안 | 장점 | 단점 | 고르지 않은 이유 |

## 결과
- 좋아지는 점
- 감수할 점
- 팀 뼈대와의 차이
```
