# 0019. 모바일 은행 데모를 브라우저 메모리에서 실행

- 상태: 채택
- 날짜: 2026-11-09
- 관련: [모바일 MVP 작업 계획](../design-drafts/NEXT_STEPS.md), [DB 재설계·이체 승인](0003-db-redesign.md)

## 배경

선택한 디자인으로 핵심 은행 업무와 상담이 이어지는 모습을 먼저 확인해야 한다. 화면 검증에 필요한 데이터는 데모로 마련하고 실제 API와 모델을 연결하는 단계는 뒤에 진행한다.

## 결정

- `frontend/`의 정적 페이지를 로컬에서 제공한다. 화면과 상호작용은 `app.mjs`, 시연 데이터·상담 응답·이체 검증은 `demo.mjs`가 담당한다.
- 상담은 수취인·금액·출금 계좌가 채워지면 이체 초안을 만든다. 직접 시작한 이체와 상담에서 시작한 이체는 같은 확인·PIN 승인 화면을 거친다.
- 잔액과 거래내역은 데모 PIN과 잔액·한도 검사를 통과한 뒤에만 바뀐다. 페이지를 새로고침하거나 로그아웃하면 시연 상태를 초기화한다.

## 검토한 대안

| 대안 | 장점 | 비용 |
|---|---|---|
| 실제 API부터 연결 | 서버 응답과 화면을 함께 검증 | 인증·승인 수명주기와 실모델 점검이 화면 시연의 선행 조건 |
| 프런트엔드 프레임워크 도입 | 컴포넌트와 라우팅을 패키지로 관리 | 초기 시연에 빌드·패키지 설정 필요 |
| 정적 화면과 데모 상태 | 별도 패키지 없이 로컬에서 시연 가능 | 실서버 연동 단계에서 데이터 경계를 다시 연결해야 함 |

## 결과

- 하나의 시연 데이터로 계좌·일반 이체·AI 상담 이체의 결과를 확인할 수 있다.
- 데모 PIN과 잔액은 브라우저 메모리 안에서만 쓰인다. 시연 화면에는 데모 표시를 붙인다.
- 팀 공통 백엔드 뼈대에 모바일 정적 화면을 추가했다.
