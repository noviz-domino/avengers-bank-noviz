# 0017. 은행 이름을 캡아메리카뱅크로: 보이는 이름만 바꾸고 코드 이름은 그대로

- 상태: 채택
- 날짜: 2026-11-06
- 관련 PR: (이 문서를 추가하는 PR)

## 결정

1. 은행 이름을 **캡아메리카뱅크(CapAmericaBank)**로 바꾼다(사용자 결정).
2. 바꾸는 곳: 사용자에게 보이는 이름과 문서.
   - API 문서 제목, README, 데모 약관("캡아메리카뱅크 카드 이용약관" 등), AI 상담원·RAG·MCP 안내문
   - 은행 이름이 들어간 상품명: 캡아메리카 입출금통장·체크카드·신용대출, 주니어 캡아메리카 적금
3. **바꾸지 않는 곳**: 파이썬 패키지 `avengers_bank`, GitHub 레포 `avengers-bank-noviz`, Docker 프로젝트 이름, 은행 이름이 아닌 상품명(스타크 자유적금, 히어로 정기예금 등), 이전 ADR(그때의 기록).
4. seed는 상품을 (종류, 상품 코드)로 찾는다. 이미 있는 상품이면 **이름을 코드 쪽 값으로 맞춘다**. 그래서 기존 DB도 서버를 다시 띄우면 새 이름이 된다. 상품명이 바뀌면 RAG 색인을 다시 만든다(`/system/rag/reindex`, 바뀐 상품만 임베딩).

## 배경

- 팀 프로젝트 이름은 AvengersBank였고, 개인 구현을 제출하면서 이름을 바꾸기로 했다.

## 검토한 대안

| 대안 | 결과 |
|---|---|
| 패키지·레포 이름까지 전부 | 거의 모든 파일의 import, Docker·CI·MCP 설정 경로가 바뀌고 팀 뼈대와 비교하기 어려워짐. 버림 |
| **보이는 이름·문서·데이터만** | **채택**. 사용자가 보는 곳은 모두 새 이름 |

## 결과

- 코드를 읽는 사람은 패키지 이름(`avengers_bank`)과 은행 이름이 다르다는 것을 알아야 한다. README 머리에 적는다.
- 이전 ADR·가이드에는 옛 이름(AvengersBank, 어벤져스은행)이 남아 있을 수 있다. 기록이라 고치지 않는다.
- "캡틴 아메리카", "어벤져스"는 마블의 상표다. 수업 과제로는 문제없지만, 공개 서비스로 낸다면 다른 이름이 안전하다.
