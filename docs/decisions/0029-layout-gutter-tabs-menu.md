# 0029. 좌우 여백 1.5배, 하단 탭을 시트로(홈·계좌·카드·상품·AI 상담), 전체 메뉴는 머리글 오른쪽 위

- 상태: 채택
- 날짜: 2026-11-11
- 관련 PR: (이 문서를 추가하는 PR)
- 관련: [ADR 0021](0021-ui-components.md) 공통 부품·하단 탭, [ADR 0027](0027-compact-layout-chat-login.md) 화면 여백 줄이기

## 배경

- 화면을 둘러보니 내용이 화면 양끝에 붙어 답답해 보였습니다. 머리글도 화면 맨 위에 바짝 붙어 있었습니다.
- 하단 탭은 "홈·상품·AI 상담·카드·전체"였습니다. 은행 앱에서 가장 자주 쓰는 **계좌**가 탭에 없고, 계좌 목록은 홈 안에만 있었습니다.
- "전체"는 매일 쓰는 목적지가 아닌데 탭 한 칸을 차지했습니다.

## 결정

1. **좌우 여백을 1.5배로**: `--ui-page-gutter` 24px → **36px**(340px 이하 화면은 16px → 24px). 공통 `main`과 카드 화면의 고정 24px도 같은 변수를 쓰게 바꿔, 모든 화면이 한 값으로 움직입니다.
2. **위 여백**: 공통 머리글(`header`) 위 여백을 4px → 16px.
3. **하단 탭은 시트처럼**: 위 모서리를 22px로 둥글게, 경계선 대신 위로 퍼지는 옅은 그림자.
4. **탭 순서**: **홈 · 계좌 · 카드 · 상품 · AI 상담**. "전체"는 탭에서 뺍니다.
5. **계좌 탭(`#accounts`) 새 화면**: 계좌 수와 합계, 입출금·예금적금 묶음(홈과 같은 `accountGroups()`), "새 계좌 만들기"(상품으로 이동).
6. **상품 목록 글자 위계**: 상품명 15px → 17px(굵게), 금리 22px → 25px. 상품명 아래 설명 13px → 12px, 금리 위아래 "연(세전)"·"기본 연 0.10%" 13px → 11px.
7. **홈 배너는 이벤트 상세 페이지로**(`#event/opening`, `#event/welcome`, `events.mjs`): 전에는 두 배너 모두 상품 목록으로만 가서 무슨 이벤트인지 알 수 없었습니다. 관리자 시스템을 만들지 않으므로 게시판·테이블 없이 배너 내용을 코드에 두고, 상세에 설명과 **바로 가입하기**(`#product/<id>/join`, 상품 상세를 건너뛰고 가입 화면부터)를 둡니다. 추천 상품의 금리·기간은 지어내지 않고 서버 상품 정보를 그대로 보여 주며, "시연용 이벤트"임을 밝힙니다.
8. **뒤로 버튼은 "열기 전 화면"으로**: 하단 탭이 없는 화면(전체 메뉴, 거래 검색, 예산, 계좌 상세·관리, 이벤트)의 뒤로는 고정된 곳(`go("menu")` 등)이 아니라 브라우저 기록을 한 칸 되돌립니다(`back` 액션, 기록이 없으면 홈). 메뉴가 생긴 뒤 "검색의 뒤로 = 메뉴", "메뉴의 뒤로 = 이전 화면(검색)"이 서로를 가리켜 둘 사이를 오가며 갇히는 문제가 있었습니다. 계좌 관리에서 별칭을 바꾼 뒤에도 앞으로 쌓지 않고 되돌아가서, 상세의 뒤로가 관리 화면으로 돌아가지 않습니다.
9. **검색은 홈이 아니라 해당 탭에**: 홈 머리글의 돋보기(거래내역 검색)를 뺐다. 계좌 거래는 **계좌 상세 안에서** 찾는다: 거래내역 위에 키워드 칸(필터를 안 열어도 바로 입력, 엔터로 검색)과 **필터** 버튼(작은 창: 기간·카테고리·금액). 입금·출금 구분과 함께 서버(`GET /transactions?account_id=`)가 거르고 찾은 거래의 입금·출금 합계를 보여 준다. 홈 "최근 거래 전체보기"는 검색 창이 아니라 **전체 거래내역 목록**(`#search`)이다. (2026-11-12 수정: 처음엔 계좌 탭 머리글에 별도 **계좌 검색** 화면을 뒀으나, 전체보기를 누르면 목록 대신 검색 폼이 떠서 계좌 상세로 옮겼다.) 카드는 카드 탭 머리글에 **카드 검색**(`#card-search`, 새 `GET /cards/transactions`)을 둡니다. 신용카드 결제는 계좌 장부에 건마다 남지 않아(결제일에 "카드 대금" 한 줄) 계좌 검색으로는 찾을 수 없었습니다. 카드 머리글은 버튼이 5개라 "발급"을 아이콘만 남겼습니다(읽어 주는 이름 "카드 발급").
10. **전체 메뉴에 메뉴 검색**: 맨 위 검색칸에 입력하면 바로가기 대신 맞는 메뉴 목록을 보여 줍니다(이름과 "같이 찾을 말", 띄어쓰기·대소문자 무시, 예: "분실" → 카드). 메뉴 목록은 `settings.mjs`의 `MENUS`.
11. **홈 머리글: 왼쪽 위는 은행 로고 + "OOO님", 오른쪽 위는 알림·전체 메뉴**: 은행 이름 글자 대신 사용자 이름(`GET /users/me`)으로 인사합니다. 종 버튼은 **알림** 화면(`#notifications`, `notifications.mjs`)을 열고, 위쪽 하위 메뉴는 **입출금내역 · 카드내역 · 혜택(광고) · 공지사항** 네 개입니다. 알림 서버(푸시·읽음 표시)는 아직 없어서 입출금·카드는 최근 거래(`GET /transactions`, `GET /cards/transactions`)를 알림처럼 보여 주고, 혜택은 이벤트 상세(`events.mjs`)로 연결하며, 공지는 이 서비스에 대한 사실만 코드에 둡니다(시연 서비스, 운영 시간, AI 상담 이용).
12. **전체 메뉴는 공통 머리글 오른쪽 위 버튼**: `header({ menu: true })`가 오른쪽 끝에 전체 메뉴 버튼을 둡니다. 탭 화면 5개(홈·계좌·카드·상품·AI 상담)에 붙입니다. 전체 메뉴 화면에는 하단 탭 대신 뒤로 버튼이 있고, 누르면 열기 전 화면으로 돌아갑니다.

## 검토한 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 계좌 탭을 대표 입출금 계좌 상세로 바로 연결 | 새 화면이 필요 없음 | 계좌가 여러 개면 탭이 한 계좌만 보여 줌. 목록 화면을 골랐음 |
| 전체 메뉴를 왼쪽 위 햄버거로 | 웹에서 흔함 | 왼쪽 위는 뒤로 버튼 자리. 국내 은행 앱처럼 오른쪽 위에 둠 |
| 알림 테이블·읽음 표시·푸시를 지금 만들기 | 진짜 알림처럼 안 읽은 개수 표시 | 거래가 생길 때 알림을 쌓는 서버 작업·마이그레이션이 필요. 화면 구성(하위 메뉴 4개)을 먼저 정하고 다음에 |
| 이벤트 게시판(테이블·API·목록 화면) | 이벤트를 추가·수정하기 쉬움 | 관리자 시스템을 만들지 않고 배너가 2개뿐이라 과함. 배너 상세 페이지로 충분 |
| 이벤트를 팝업(바텀시트)으로 | 화면 이동이 없음 | 설명·추천 상품·참여 방법·버튼을 담기엔 좁음 |
| 여백을 화면마다 따로 늘리기 | 화면별로 미세 조정 가능 | 값이 흩어져 다음에 또 맞춰야 함. 변수 하나로 모음 |

## 결과

- 좋아지는 점: 내용이 화면 끝에서 떨어져 덜 답답합니다. 계좌가 탭 한 번으로 보입니다. 전체 메뉴는 어느 탭 화면에서나 같은 자리에 있습니다. 여백 값이 변수 하나로 모였습니다.
- 감수할 점: 본문 폭이 24px 줄어 계좌 줄(아이콘·이름·금액·이체 버튼)이 빠듯합니다. 계좌번호가 하이픈에서 끊기지 않게 한 줄로 고정하고 이체 버튼 안쪽 여백을 줄였습니다. 전체 메뉴가 탭보다 한 번 더 멀어졌습니다(머리글 버튼).
- 팀 뼈대와의 차이: 팀 뼈대에는 모바일 웹이 없습니다. 하단 탭 구성은 이 레포의 ADR 0021을 이 문서가 바꿉니다.
